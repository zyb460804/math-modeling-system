# outputs/review_section_checklists.md

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

> 用于把论文审稿进一步细化到“按章节逐段检查”的子清单，适合改稿时直接逐项勾查。

---

## 一、使用方式

最稳妥的用法不是全文通读后凭感觉改，而是按章节逐段核查：
1. 先查这一节有没有回应题目要求；
2. 再查这一节有没有完成自己的职责；
3. 最后查这一节是否和前后文衔接。

---

## 二、摘要审稿清单

### 必查项
- [ ] 第一句是否写清研究对象与核心任务
- [ ] 是否写出主干模型或主线框架，而不是罗列全部模型名
- [ ] 是否明确写出关键结果，而不是只说“效果较好”
- [ ] 是否写出检验、稳健性或误差分析
- [ ] 是否落到实际启示、决策价值或应用意义

### 高频问题
- 只写“建立模型”，不写结果
- 模型名堆砌过多
- 摘要像目录缩写，不像完整短文
- 结果和正文主线不一致

### 快速改法
- 用“问题 → 方法 → 结果 → 检验 → 结论”五句法重写
- 只保留 1—2 个最关键模型名
- 至少补 1 个定量结果或清晰趋势判断
- 若使用组合模型，补一句“谁负责主任务、谁负责补充或调参”

---

## 三、问题重述与问题分析审稿清单

### 必查项
- [ ] 是否重新用自己的话说明题目任务，而不是照抄题面
- [ ] 是否区分了各子问题的职责与关系
- [ ] 是否识别题目本质类型（评价 / 预测 / 优化 / 机理 / 分类）
- [ ] 是否说明最终输出是什么
- [ ] 是否为后文模型选择做了铺垫

### 高频问题
- 只复述题目背景，没有分析任务本质
- 子问题彼此割裂
- 只分析关键词，不分析最终输出
- 问题分析写完后和后文模型不衔接

### 快速改法
- 加一句“本题本质属于……”
- 加一句“前两问服务于后一问的决策输出”
- 明确写出“最终要得到什么结果”
- 对 A / B / C 题分别自查：A 题是否写出机理和边界，B 题是否写出比较和建议，C 题是否写出链式闭环

---

## 四、模型假设与符号说明审稿清单

### 模型假设必查项
- [ ] 每条假设是否确有必要
- [ ] 每条假设是否不会明显改变题目本质
- [ ] 是否避免“完全理想化”表述
- [ ] 是否说明最敏感假设或适用边界

### 符号说明必查项
- [ ] 核心变量、参数、集合是否都已定义
- [ ] 符号在全文前后一致
- [ ] 单位、上下标、时间下标是否统一
- [ ] 复杂公式里的关键符号是否能在表中找到

### 高频问题
- 假设过强，等于偷换题意
- 符号表不全，正文临时冒出新符号
- 同一符号在不同章节含义不同

### 快速改法
- 删掉无作用假设
- 补一张核心符号表
- 把最关键假设后面补一句“该假设主要用于……”

---

## 五、模型建立审稿清单

### 必查项
- [ ] 是否说明为什么选这个模型
- [ ] 是否明确变量、目标函数、约束或评价逻辑
- [ ] 模型之间是否分工清楚
- [ ] 是否体现“预处理 → 中间层 → 决策层”或类似闭环
- [ ] 是否避免为了复杂而堆模型
- [ ] 若是参数优化型组合，是否写清“主模型 + 超参数优化器”而不是双主模型
- [ ] 若涉及互斥、启停、固定费用或指派逻辑，是否明确 0-1 变量 / 大 M 约束的现实含义

### 高频问题
- 只写公式，不解释公式代表什么
- 模型很多，但职责说不清
- 评价、预测、优化混在一起没有主线
- 只做到中间分析层，没有接入决策层
- 把 RF + GA、XGBoost + 贝叶斯优化误写成双主模型并列
- 写了 0-1 / 大 M 约束，却不解释其控制的现实逻辑
- A / B / C 题的模型重心与写作口径没有对齐

### 快速改法
- 每个模型前补一句“用于解决什么问题”
- 每个模型后补一句“输出将进入哪一步”
- 砍掉无职责模型
- 参数优化型组合改写成“主模型 + 超参数优化器”
- 对 0-1 变量或大 M 约束补一句“它对应哪个现实动作或逻辑条件”
- 对 A / B / C 题分别补：A 题机理与边界，B 题比较与建议，C 题链式输入输出

---

## 六、求解与算法设计审稿清单

### 必查项
- [ ] 是否说明求解流程而不只是给代码结果
- [ ] 参数设置是否有依据
- [ ] 算法是否与变量类型匹配
- [ ] 若用智能算法，是否交代运行次数、终止条件、稳定性
- [ ] 若用机器学习，是否交代训练 / 测试或验证方式
- [ ] 若用 LSTM / GRU 等深度学习，是否交代学习率、正则化 / Dropout、梯度裁剪、初始化或 BatchNorm 等稳定性控制

### 高频问题
- 离散问题误用 PSO
- 小样本直接上复杂模型
- 只给流程图，不解释每一步作用
- 只给迭代图，不证明结果可信
- 深度学习模型没有训练稳定性说明

### 快速改法
- 补“数据处理 → 参数初始化 → 迭代更新 → 输出结果”的文字流程
- 补参数表
- 补替代算法比较或方法边界说明
- 若用深度学习，补 1 句训练稳定性控制 + 1 组测试指标

---

## 七、模型检验与稳健性审稿清单

### 必查项
- [ ] 是否单独设置“模型检验”或“稳健性分析”小节
- [ ] 是否按模型类型做对应检验，而不是泛泛写“模型有效”
- [ ] 是否同时覆盖误差 / 稳定性 / 边界中的至少两项
- [ ] 是否解释检验结果意味着什么
- [ ] 链式建模中是否同时检验中间层与决策层
- [ ] 组合模型是否与基础模型做了对照

### 高频问题
- 完全没有检验
- 只有误差指标，没有稳定性分析
- 只有灵敏度图，没有文字解释
- 检验结果与正文主结论脱节
- 组合模型没有基础模型对照

### 快速改法
- 先补 1 个最关键检验
- 再补 1 个参数扰动或情景分析
- 最后补 1 句边界说明
- 若是组合模型，再补基础模型对照

---

## 八、结果分析审稿清单

### 必查项
- [ ] 是否解释“结果说明了什么”
- [ ] 是否说明“为什么会出现这个结果”
- [ ] 是否和基准方案 / 不同对象 / 不同情景做比较
- [ ] 是否把结果翻译成建议或动作
- [ ] 图表后是否有文字结论
- [ ] 链式建模中是否写清“中间层输出 → 决策层输入”的落地句

### 高频问题
- 只报数值，不解释原因
- 只说最优，不说明优在何处
- 只做预测，不落到后续决策
- 图表很多，但正文不分析

### 快速改法
- 每段按“现象—原因—启示”重写
- 每张图后补一句结论
- 每类结果至少补 1 句现实落地表达

---

## 九、结论与建议审稿清单

### 必查项
- [ ] 是否回扣全文主线而不是重复摘要
- [ ] 是否提炼出最核心的 2—3 条结论
- [ ] 是否说明模型局限与适用边界
- [ ] 是否给出可执行建议或后续工作方向

### 高频问题
- 结论只是把正文复制一遍
- 不承认局限，写得过满
- 没有建议，停在“模型有效”

### 快速改法
- 先总结主结论
- 再写 1 条现实建议
- 最后写 1 条局限与改进方向

---

## 十、交稿前最后一轮逐节快扫

- [ ] 摘要写了结果
- [ ] 问题分析写了题型本质
- [ ] 假设不过强
- [ ] 符号前后一致
- [ ] 模型职责清楚
- [ ] 求解过程可复现
- [ ] 检验单独成节
- [ ] 结果有解释、有比较、有建议
- [ ] 结论承认边界
- [ ] A / B / C 题的答题重心与当前题目类型一致
- [ ] 参数优化型组合没有被写成双主模型
