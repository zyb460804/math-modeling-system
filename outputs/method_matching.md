# outputs/method_matching.md

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 用于沉淀题型—建模思路—模型—算法—风险的匹配关系。

> **定位**：本文件是建模选模层的**主入口**。包含完整的题型—模型—算法—风险对照表和分题型匹配细则。当需要"审题选模"时，优先使用本文件。
> **相关文件**：`model_selection_flow.md`（选模决策流程）、`model_selection_quick_table.md`（一页式速查表）

---

## 一、统一实战调用入口

当用户给出一道题并要求解题、写论文或生成完整作品时，本文件只负责“审题选模”环节，必须接入统一主链路：

**任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌**

推荐调用顺序：
1. 先读 `outputs/task_router.md`，判断任务是单题建模、论文改稿、代码生成还是提交冲刺。
2. 若涉及附件、字段、参数、指标或原始数据，先读 `outputs/data_cleaning_standards.md`，统一字段含义、单位、指标方向、缺失异常处理和参数来源。
3. 再用本文件判断题型、主模型、备选模型、误用风险和最低检验包。
4. 进入 `outputs/algorithm_templates.md`，把模型路线落成可复现算法流程。
5. 进入 `outputs/writing_templates.md`、`outputs/table_templates.md`、`outputs/figure_templates.md`，把模型路线同步写进论文、表格和图示。
6. 提交或答辩前必须进入 `outputs/final_quality_gate.md`，检查是否存在 P0 阻断项。

输出模型路线时必须包含：题型判断、最终输出、主模型、备选模型、输入数据要求、最低检验包、论文落点、答辩风险。缺少真实数据或运行结果时，只能写【待补】，不得编造数值、精度、p 值或排名。

---

## 二、总原则

1. 先判断题目本质，再选模型。
2. 先选基础模型，再决定是否需要改进或融合。
3. 方法说明必须包含：适用条件、优点、局限、风险。
4. 复杂不等于高分，贴题才等于高分概率更高。

## 二、题型—思路—方法—算法—风险对照表

| 题型 | 识别信号 | 建模思路 | 推荐模型 | 常用算法/求解 | 主要风险 |
|---|---|---|---|---|---|
| 评价类 | 多指标、排序、优选、打分 | 建指标体系 + 赋权 + 综合评价 | AHP、熵权法、TOPSIS、灰色关联、模糊综合评价、DEA | 标准化、权重计算、优劣解距离、效率分析 | 指标体系随意；权重无依据；评价后不解释 |
| 预测类 | 未来趋势、需求、销量、波动 | 根据时间序列或因果关系预测未来 | Logistic、灰色预测、ARMA/ARIMA、指数平滑、回归、BP/树模型 | 参数估计、训练验证、误差评估 | 不区分趋势型/周期型/不规则型；只追模型复杂 |
| 优化类 | 最优、最小/最大、调度、配置、路径 | 明确目标函数、约束、决策变量 | 线性规划、整数规划、非线性规划、多目标规划、动态规划 | 单纯形法、分支定界、梯度法、GA、PSO、模拟退火 | 目标和约束写不清；算法与变量类型不匹配 |
| 统计分析类 | 影响因素、关系分析、显著性 | 描述统计 + 相关/回归/检验 | Pearson、Spearman、卡方检验、回归分析 | 参数估计、显著性检验、残差分析 | 把相关当因果；样本条件不检验 |
| 机理分析类 | 物理、生物、传热、传染、系统演化 | 从基本规律出发建方程 | 微分方程、差分方程、系统动力学 | 数值积分、参数拟合 | 只套方程，不解释物理意义 |
| 聚类/分类类 | 分群、识别、鉴别、标签 | 无监督或监督识别模式 | K-Means、层次聚类、GMM、SVM、决策树、随机森林 | 聚类迭代、训练分类器、交叉验证 | 无监督和监督混用；指标解释弱 |
| 图与网络类 | 最短路、连通、选址、网络结构 | 图建模 + 路径/网络分析 | Dijkstra、Floyd、TSP、复杂网络指标 | 最短路搜索、启发式搜索 | 图结构定义不清；边权设置随意 |
| 数据预处理类 | 缺失、异常、降维、编码 | 先清洗数据，再进入主模型 | 插值、3σ、箱线图、标准化、编码、PCA | 清洗、变换、降维 | 把预处理当主模型；处理依据不说明 |
| 多目标决策类 | 多个目标同时优化 | 权衡目标、构建 Pareto 思路 | 多目标规划、NSGA-II、MOPSO、字典序优化、分层决策 | 权重法、Pareto 搜索、优先级约束 | 目标冲突没解释；权衡依据不清 |
| 风险预警类 | 风险评分、预警阈值、违约/故障/异常 | 连续评分 + 阈值分层 + 触发规则 + 干预动作 | Logistic、随机森林、XGBoost、贝叶斯网络、AHP/熵权、评分卡 | 分类训练、阈值设定、风险排序、阈值扰动 | 指标无因果逻辑；阈值拍脑袋；只报准确率 |

## 三、重点题型匹配细则

### 1. 评价类
- **无数据支撑赋权**：优先 AHP。
- **有数据支撑赋权**：优先熵权法。
- **需要排序**：优先 TOPSIS。
- **多投入多产出效率**：优先 DEA。
- **边界模糊、主观性强**：优先模糊综合评价。
- **最稳妥组合**：熵权法 + TOPSIS，前者负责客观赋权，后者负责综合排序。
- **主客观都要兼顾**：AHP + 熵权法，前者吸收专家判断，后者吸收数据离散度，适合供应商选择、绩效评价这类既要讲经验又要讲数据的题。
- **小样本且指标有冲突**：TOPSIS + 灰色关联分析，前者给全局排序，后者补局部接近性与稳定性。
- **高维评价或识别**：PCA + SVM 更适合写成“先降维去噪，再分类识别”，不要把 PCA 直接写成最终评价结论。

**易误用**：
- 指标一多就直接上神经网络。
- 权重来源不解释。
- 得到排序后不做现实分析。
- 只算权重，不把权重接入最终评价模型。

### 2. 预测类
- **单调趋势**：Logistic、灰色预测、指数平滑。
- **周期序列**：季节模型、ARMA/ARIMA。
- **不规则序列**：回归、树模型、组合模型。
- **多变量时序**：BP、LSTM 类方法可考虑，但必须有足够数据支撑。
- **非线性基线建模**：可先用随机森林回归打底，再决定是否升级到组合模型。
- **组合模型分工原则**：如 ARIMA-LSTM 侧重“线性趋势 + 非线性残差”，GM(1,1)-BP 侧重“小样本趋势 + 非线性修正”，应明确每个模块各解决什么问题。
- **参数优化型组合**：RF+GA、XGBoost+贝叶斯优化这类更适合写成“预测主模型 + 超参数优化器”，不要误写成两个主预测器并列。
- **深度时序升级条件**：只有当样本量、序列长度和训练稳定性说明都足够时，LSTM / GRU / Attention 才值得上场。
- **默认检验包**：至少补误差指标、残差/测试集表现，并说明预测结果如何接入后续补货、调度或策略层。

**易误用**：
- 数据量很小却硬上深度学习。
- 不做训练集/测试集或误差分析。
- 预测完不解释变量影响。
- 没有把预测结果接入后续补货、调度、策略优化。
- 组合模型只报名称，不说明基础模型与改进模块的职责分工。

### 3. 优化类
- **目标和约束都线性**：线性规划。
- **变量必须整数/0-1**：整数规划或 0-1 规划。
- **目标或约束非线性**：非线性规划。
- **多目标并存**：多目标规划。
- **目标优先级天然明确且权重争议大**：字典序优化或分层决策，先满足安全、合规、容量等高优先级目标，再优化成本、效率或满意度。
- **非凸/大规模/难精确求解**：GA、PSO、模拟退火等智能优化。
- **连续变量非凸优化**：PSO 常作为优先备选。
- **离散变量优化**：优先 GA、整数规划或其他离散优化方法，不要直接套 PSO。
- **逻辑约束明显**：若存在互斥、启停、固定费用、指派关系，应优先考虑 0-1 规划、大 M 约束或整数规划建模。
- **组合优化原则**：GA+SA、PSO+TS、ACO+Greedy 等组合更适合“全局搜索 + 局部精修”或“初始解加速 + 迭代优化”这类明确短板场景，而不是为了显得高级而拼接。
- **默认检验包**：至少补基准方案对比、情景分析或参数扰动，并解释方案结构为什么合理。

**易误用**：
- 连续变量问题只因“会写”就用 GA。
- 小规模凸问题不先试精确算法。
- 没有清楚给出目标函数与约束。
- 只给优化结果，不解释结果如何转化为可执行方案。
- 组合算法没有说明谁负责全局搜索、谁负责局部改进。

### 4. C 题链式建模
- **典型流程**：数据清洗/特征压缩 → 分类/评分/预测 → 优化决策 → 不确定性分析。
- **风险治理流程**：筛选对象 → 连续风险评分 → 阈值分层预警 → 分级干预或资源优化。
- **常见模块**：PCA、聚类、Logistic / 随机森林 / XGBoost、动态规划、多目标规划、鲁棒优化、蒙特卡洛。
- **适用场景**：风控、供应链、农作物种植、动态定价、补货决策、企业评分。
- **闭环判断**：必须写清“中间层输出 → 决策层输入”，并分别检验中间层结果与最终方案稳定性。

**易误用**：
- 只停留在数据分析阶段，不进入最终决策。
- 只做预测，不把预测结果作为优化输入。
- 忽略噪声、波动和鲁棒性。
- 只说形成闭环，却没有写清输入输出衔接。
- 分类准确率很高却不解释标签结构、样本分布和误判类型。
- 风险预警只给等级或标签，没有连续评分、阈值依据和干预动作。

### 5. 环境 / 机理 + 优化综合题
- **适用场景**：污染扩散、生态治理、能源调度、交通排放、资源配置等既要解释机制又要给方案的题。
- **推荐主线**：先用机理或统计模型解释变量关系，再用优化模型生成治理、调度或配置方案。
- **模型分工**：机理层负责“为什么变化”，优化层负责“怎么调整”，情景层负责“不同条件下方案是否稳”。
- **高分检验**：至少补参数扰动、情景对照或约束可行性核查。

**易误用**：
- 只写机理解释，不给可执行方案。
- 只做优化求解，不说明目标和约束来自什么机制。
- 多目标权重拍脑袋，没有解释偏好、优先级或 Pareto 折中。

## 四、有效创新 vs 表面复杂

| 类型 | 有效创新 | 表面复杂 |
|---|---|---|
| 模型选择 | 因题制宜，补充关键约束 | 把多个热门模型机械拼接 |
| 参数设计 | 自适应参数、阈值有解释 | 随意调参不解释 |
| 模型联动 | 先聚类再回归、先评价再优化等有明确逻辑 | 模型之间互不支撑 |
| 结果表达 | 图表支持决策解释 | 只追求图表花哨 |
| 论文写法 | 摘要和结果分析突出价值 | 大量空话套话 |

## 五、选题阶段的快速匹配规则

### 1. 先看输出，再定题型
- **最终要排序/优选**：优先按评价类处理。
- **最终要预测未来**：优先按预测类处理。
- **最终要给最优方案**：优先按优化类处理。
- **最终要解释影响关系**：优先按统计分析类处理。
- **最终要刻画系统演化机制**：优先按机理分析类处理。
- **最终要分群或识别对象类别**：优先按聚类/分类类处理。

### 2. 先看团队能力，再定方法深度
- **推导强**：A 题、机理模型、规划模型更适合。
- **数据处理强**：C 题、链式建模、分类/预测/优化联动更适合。
- **综合分析与写作强**：B 题、评价+预测+优化组合更适合。
- **基础薄弱**：优先选能用成熟基础模型闭环的题，不要先冲复杂组合模型。

### 3. 先看数据条件，再定模型上限
- **小样本、短序列**：优先灰色预测、回归、指数平滑、基础评价模型。
- **大样本、多字段**：可考虑随机森林、XGBoost、聚类、链式建模。
- **变量和约束清楚**：优先规划模型。
- **机制清楚但数据不多**：优先机理模型或仿真模型。

### 4. 选题时的避坑判断
- 如果一个题**主线说不清**，再多模型也不稳。
- 如果一个题**只能分析，落不到决策层**，在写作上容易发虚。
- 如果一个题**检验很难展开**，后期论文闭环风险更高。
- 如果一个题**需要临场现学大量陌生背景知识**，一般不适合作为稳妥题。

## 六、默认推荐顺序

1. 先用最能解释题目的基础模型打底。
2. 若基础模型不能覆盖关键难点，再做针对性改进。
3. 若需要冲高分，再考虑模型联动或参数改进。
4. 每一步都要回答：为什么比替代方案更合适。

## 七、代码模板的使用边界

### 1. TOPSIS
- 适合作为多指标排序模块。
- 不能跳过正负向统一与标准化。
- 若题目需要“为什么这样赋权”，需配合熵权法或 AHP。

### 2. 熵权法
- 适合作为客观赋权模块。
- 不能单独代替综合评价。
- 某列指标无差异时，需谨慎处理权重有效性。

### 3. PCA
- 适合作为高维数据压缩、风险指数构建、特征提取工具。
- 不能直接代替最终预测、分类或决策模型。
- 必须说明保留主成分数的依据。

### 4. 随机森林回归/分类
- 适合作为非线性基线模型。
- 必须保留训练/测试拆分、误差评估与特征重要性解释。
- 若直接用于比赛论文，需补充变量含义和业务解释。

### 5. PSO
- 适合作为连续变量、非凸优化问题的近优搜索算法。
- 不应默认用于离散变量优化。
- 若采用 PSO，最好补充参数设置和多次运行稳定性说明。

### 6. Logistic 微分方程
- 适合作为增长、传播、饱和类机理模型骨架。
- 不应脱离参数现实含义单独使用。
- 必须解释初值、增长率、容量上限的业务或物理意义。

## 九、最强版联动入口

- `outputs/case_to_method_route_library.md`：按题面信号直接反推“主路线 + 最小检验包 + 写作落点”。
- `outputs/code_template_playbook.md`：当路线已定、需要落到代码模板和论文写法时优先联动。
- `outputs/algorithm_selection_red_flags.md`：当你犹豫某模型能不能上时，先查禁区再决定。
- `outputs/model_chain_blueprints.md`：当题目明显是“识别/预测/评分 → 决策”的链式结构时优先联动。
- `outputs/high_score_expression_library.md`：当模型路线已经明确，但你不会把方法和结果写得像高分稿时优先联动。
