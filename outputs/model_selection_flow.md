# outputs/model_selection_flow.md

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

> 用于沉淀数学建模比赛中的模型选择流程、题型识别路径与常见分歧时的决策规则。

> **定位**：本文件是选模的**决策流程**。按"最终输出→题型→主模型→辅助模型→检验"的步骤式决策树展开。当 method_matching.md 给出多个候选方案、需要进一步决策时使用本文件。
> **主入口**：`method_matching.md`
> **速查版**：`model_selection_quick_table.md`

## 一、总原则

1. **先识别问题本质，再选模型。**
2. **先选主干模型，再考虑辅助模型。**
3. **先保证闭环，再追求复杂。**
4. **模型选择必须同时满足三件事：贴题、可解、可写。**
5. **不能因为“会写某算法”就把它当默认方案。**

---

## 二、最稳妥的选模总流程

### 第 1 步：先判断最终输出是什么
- 排序 / 优选 → 评价类
- 未来趋势 / 数值预测 → 预测类
- 最优方案 / 配置 / 路径 → 优化类
- 影响关系 / 显著性 → 统计分析类
- 演化规律 / 传播机制 → 机理分析类
- 分群 / 分类 / 识别 → 聚类或分类类

### 第 2 步：再判断核心对象是什么
- 指标体系 → 评价模型优先
- 时间序列 → 预测模型优先
- 资源与约束 → 规划/优化优先
- 多样本特征 → 聚类/分类/回归优先
- 机制与反馈关系 → 微分方程/仿真优先

### 第 3 步：再判断数据条件与约束条件
- 样本小 / 序列短 → 先基础模型
- 数据大 / 特征多 → 可考虑机器学习或链式建模
- 约束清楚 → 优先规划模型
- 机制清楚但数据弱 → 优先机理模型

### 第 4 步：再判断是否需要辅助模型
- 权重问题 → AHP / 熵权法
- 降维问题 → PCA
- 非凸优化 → GA / PSO / SA
- 多目标冲突 → 多目标优化
- 不确定性明显 → 蒙特卡洛 / 鲁棒优化 / 情景分析

### 第 5 步：最后判断写作与检验是否跟得上
- 能不能解释为什么选这个模型？
- 能不能做一项扎实检验？
- 能不能把结果落到现实建议？

若三项里有两项答不上来，应降复杂度，回退到更稳的主干模型。

### 第 6 步：判断是否真的需要组合模型
- 基础模型是否已经能完成主任务？
- 当前短板到底是权重、排序、效率、残差、波动、全局搜索还是局部精修？
- 第二个模型是否恰好只弥补这个短板？
- 组合后能否做对照、检验和职责解释？

若答不出这四点，优先保留单一主干模型。

### 第 7 步：判断链式建模是否真的闭环
- 中间层输出是否能作为后续优化、调度、分级或治理方案的明确输入？
- 决策层目标函数、约束或优先级是否真的使用了中间层结果？
- 是否同时准备了中间层检验与最终方案层检验？
- 若拿掉中间层，最终方案是否会明显失去依据？

若这四点说不清，就不要轻易宣称“形成闭环”。

## 三、题型识别流程

### 1. 评价类
判断信号：
- 出现“综合评价、优选、排序、打分、指标体系”

默认流程：
- 构建指标体系 → 权重确定 → 综合评价 → 排序解释 → 稳定性分析

优先模型：
- AHP、熵权法、TOPSIS、模糊综合评价、DEA

补充判断：
- **有数据且需要客观赋权** → 熵权法优先
- **主观判断较强** → AHP 或 AHP + 客观赋权
- **边界模糊、等级划分明显** → 模糊综合评价
- **多投入多产出效率** → DEA
- **单模型无法同时兼顾赋权与排序** → 再考虑“熵权 + TOPSIS”“DEA + TOPSIS”等职责清晰组合

### 2. 预测类
判断信号：
- 出现“预测、未来、趋势、波动、需求变化”

默认流程：
- 分析序列特征 → 选择预测模型 → 误差评估 → 趋势解释 → 接后续决策

优先模型：
- 灰色预测、指数平滑、ARIMA、回归、随机森林回归

补充判断：
- **先快后缓并趋于饱和** → Logistic
- **小样本、短序列** → 灰色预测优先
- **线性时序结构明显** → ARIMA / SARIMA
- **非线性关系较强但样本足够** → 随机森林、BP、LSTM
- **需要组合模型** → 必须明确“谁提取主结构，谁修补残差/波动/状态转移”
- **若是 RF + GA / XGBoost + 贝叶斯优化** → 更稳妥写成“预测主模型 + 超参数优化器”，不要当成双主预测器并列

### 3. 优化类
判断信号：
- 出现“最优、最大/最小、调度、配置、路径、成本收益平衡”

默认流程：
- 明确变量 → 写目标函数 → 写约束 → 求解 → 方案对比 → 情景检验

优先模型：
- 线性规划、整数规划、非线性规划、多目标规划、动态规划、GA、PSO

补充判断：
- **变量本质是整数或 0-1** → 优先整数规划
- **存在互斥、启停、固定费用、指派逻辑** → 优先考虑 0-1 规划、大 M 约束或整数规划建模
- **目标和约束都线性** → 先尝试精确规划，不要默认上智能算法
- **连续变量且非凸** → 再考虑 PSO / GA / SA
- **需要全局搜索 + 局部改进** → 可考虑 GA + SA、PSO + TS
- **主干约束能精确建模，但附加复杂约束难求解** → 可考虑“LP/IP + 启发式”组合
- **若最终方案需要落地执行** → 必须预留基准方案对比与情景/灵敏度检验位置

### 4. 统计分析类
判断信号：
- 出现“影响因素、关系分析、显著性、相关性”

默认流程：
- 描述统计 → 相关分析 → 回归分析 → 显著性与残差检验 → 机制解释

优先模型：
- 相关分析、回归分析、卡方检验、方差分析

### 5. 机理分析类
判断信号：
- 出现“传播、扩散、增长、演化、反馈、动力学”

默认流程：
- 抽象机制 → 建方程 → 数值求解 → 参数分析 → 机制解释

优先模型：
- 微分方程、差分方程、系统动力学、仿真模型

补充判断：
- **存在容量上限或自限机制** → Logistic 等增长模型更合适
- **方程能写，但参数意义说不清** → 不应急着上机理模型

### 6. 聚类 / 分类类
判断信号：
- 出现“分群、识别、判别、标签、类别”

默认流程：
- 数据预处理 → 聚类或分类 → 指标评估 → 类别解释 → 差异化策略

优先模型：
- K-means、层次聚类、GMM、Logistic、SVM、随机森林、XGBoost

## 四、数据条件判断规则

### 1. 小样本 / 短序列
优先：
- 灰色预测、回归、指数平滑、基础评价模型、机理模型

避免：
- 一上来就深度学习
- 复杂集成模型无对照使用

### 2. 大样本 / 多特征
优先：
- 随机森林、XGBoost、聚类、分类、链式建模

注意：
- 必须保留解释环节
- 不要只追精度
- 若升级到深度学习或组合模型，需同时确认训练稳定性、测试评估和答辩解释口径

### 3. 数据缺失 / 异常明显
优先：
- 先做清洗、插值、异常值检测、标准化、降维

原则：
- 预处理是前置步骤，不是最终模型
- PCA、因子分析、聚类等中间工具不能直接替代最后结论

### 4. 机制清楚、数据较弱
优先：
- 微分方程、差分方程、仿真、规则模型

原则：
- 用机理解释替代纯黑箱拟合

### 5. 变量类型判断
- **连续变量**：线性规划、非线性规划、PSO 等更自然
- **离散 / 0-1 变量**：整数规划、0-1 规划、GA、TS 等更自然
- **若变量类型和算法编码不匹配**：优先换方法，不要硬改问题去适配算法

## 五、何时用基础模型，何时做改进

### 1. 先用基础模型的情况
- 题目主线还没完全看清
- 数据条件一般
- 时间紧
- 团队对复杂模型解释把握不足
- 需要优先保证写作闭环

### 2. 可以做改进的情况
- 基础模型短板明确
- 改进是针对题目真实难点，而不是为了显得高级
- 能做出对照或检验，证明改进有效

### 3. 最稳妥改进方向
- 加关键约束
- 做参数优化
- 做模型联动
- 做情景分析和稳健性增强
- 做更贴题的指标设计

### 4. 最不稳的伪改进
- 只把热门模型拼接在一起
- 只加一个复杂算法名词，没有职责分工
- 没有基础模型对照，无法证明升级有效
- 改进后写不清、答不清、检验也跟不上

## 六、常见选模误区

1. 把模型复杂度当成得分来源。
2. 把现成代码当成选模依据。
3. 只看题目关键词，不看最终输出。
4. 只看能不能算，不看能不能解释和写出来。
5. 评价、预测、优化三类任务混成一团。
6. 链式建模只做到中间层，不做到决策层。
7. 没有检验预案就先上复杂模型。

---

## 七、赛中快速决策规则

### 规则 1
如果两种模型都能做，优先选**更贴题、更容易解释**的。

### 规则 2
如果两道题都能做，优先选**更容易形成闭环**的。

### 规则 3
如果一个模型需要大量临场补背景知识，优先换成熟主干模型。

### 规则 4
如果一个题结果难落地到建议，后续写作风险大，应谨慎。

### 规则 5
如果复杂模型不能明显优于基础模型，就不要强上。

---

## 八、答辩用短版选模逻辑

- “我们先看最终输出要求，再判断题型，而不是只看表面关键词。”
- “我们优先选择能够解释问题主线的基础模型，再根据题目真实难点决定是否做改进。”
- “模型选择不仅考虑能不能算，还考虑能不能检验、能不能写清、能不能落地。”
