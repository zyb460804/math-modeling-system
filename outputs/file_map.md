## 总体结构概览

当前项目的**主工作区仅指 `E:\数学建模`**。本文件地图默认只纳入这个目录中的数学建模资料、脚手架、提示词和输出库，**不纳入其他附加工作目录中的统计建模资料包**。

### A. 已建立的标准工作区
- `prompts/`：任务提示词
- `outputs/`：知识库与规则沉淀区
- `01_真题/` ~ `09_参考资料/`：后续归档目录
- `05_我的作品/占位区|个案工作区|归档区`：作品迭代区

### B. 当前项目内的原始数学建模资料包

- `数学建模国赛零基础3天极限速成讲义！.pdf`

### C. 作用边界说明
- 本地图服务对象是：**数学建模国赛/美赛/校赛这类通用数学建模训练与比赛工作流**。
- 不纳入：统计建模大赛专项资料、统计竞赛专用选题库、统计建模比赛模板包。
- 后续若要做统计建模，应单独起一个并行库，不与本项目混用。

整体判断：当前资料量已经足够支撑“审题—建模—算法—写作—答辩—复盘”的完整闭环，适合先按“总览材料 → 方法讲义 → 代码模板 → 写作模板 → 反例与答辩材料”的顺序使用。

在此基础上，当前项目已进入“最强版升级阶段”：后续不再只是补母库，而是继续向 **高分样本库、代码说明书库、题型作战包、图表策略库、冲刺改稿包** 五个方向加厚。

本轮又补入了一层“系统胶水层”，核心文件包括：
1. `outputs/production_specs.md`
2. `outputs/asset_registry.md`
3. `outputs/task_router.md`
4. `outputs/case_feedback_loop.md`
5. `prompts/00_route_task.md`
6. `prompts/22_case_feedback_loop.md`

这层的作用不是新增知识点，而是把已有母库真正串成“先分流、再执行、做完再回灌”的闭环系统。

当前建议把增强层理解为五个补强方向：
1. **高分样本层**：`winning_paper_pattern_library.md`、`high_score_expression_library.md`
2. **路线作战层**：`case_to_method_route_library.md`、`model_chain_blueprints.md`
3. **代码说明书层**：`code_template_playbook.md`、`algorithm_selection_red_flags.md`
4. **终稿冲刺层**：`paper_upgrade_playbook.md`、`visualization_strategy_library.md`
5. **答辩压缩层**：`defense_short_answers.md`、`defense_followup_chains.md`、`defense_opening_and_closing.md`

在这五层之上，现在新增第六层：
6. **系统调度层**：`production_specs.md`、`asset_registry.md`、`task_router.md`、`case_feedback_loop.md`

进一步说，当前 `outputs/` 已经形成“母库 + 子库 + 审稿调度库”的三级结构：母库负责总原则，子库负责专项模板与避坑，`review_*` 文件负责最后阶段按优先级落地改稿。
