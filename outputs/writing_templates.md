## 一、统一论文生产入口

本文件负责把题目、模型、代码结果、表格和图示组织成论文表达，不替代真实建模与真实运行。写论文时必须接入统一主链路：

**任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌**

当用户说“给你题目，帮我解题并写论文”时，推荐执行：
1. 先用 `outputs/task_router.md` 判断任务入口，明确当前是 demo 还是 real_case。
2. 用 `outputs/data_cleaning_standards.md` 对齐数据字段、单位、指标方向、缺失异常和参数来源。
3. 用 `outputs/method_matching.md` 和 `outputs/algorithm_templates.md` 确定模型路线与算法流程。
4. 先生成问题分析、模型假设、符号说明和模型建立，再生成代码、结果表、图示和结果分析。
5. 摘要必须最后写，且只能引用已经跑通或明确给出的真实结果。
6. 提交前必须用 `outputs/revision_checklist.md` 和 `outputs/final_quality_gate.md` 做 P0 检查。

写作中禁止把演示数据、占位结果、未运行代码、假设指标写成真实结论。凡缺题面、缺字段、缺代码输出、缺检验或缺图表编号处，一律标注【待补】。

## 二、摘要模板

### 通用高分模板
> 针对题目中关于【问题对象】的【核心任务】，本文首先基于【数据/机制/约束】对问题进行抽象，建立【模型 1】用于解决【子问题 1】；随后建立【模型 2】用于解决【子问题 2】；最后结合【算法/检验方法】对模型结果进行分析与验证。结果表明：【核心结果 1】、【核心结果 2】。进一步的【灵敏度/误差/稳健性】分析说明，该模型在【应用场景】下具有较好的【稳定性/解释性/可操作性】。本文方法可为【实际决策对象】提供参考。

### C 题链式建模摘要模板
> 针对【业务场景】中的【决策问题】，本文构建“数据预处理—【分类/评分/预测】—【优化决策】—不确定性检验”的链式建模框架。首先利用【PCA/聚类/特征筛选】提取关键特征，并建立【随机森林/Logistic/XGBoost/LSTM】模型完成【识别/预测】任务；随后将中间结果作为优化输入，构建【动态规划/多目标规划/鲁棒优化】模型得到最终方案。结果表明：【核心结论】。进一步通过【蒙特卡洛/情景分析/灵敏度分析】验证了模型在波动环境下的稳定性。

### 写作格式补充规则
- 摘要尽量控制在 1 页内，按“问题—方法—结果—结论”闭环组织。
- 关键词通常写 3–5 个，优先覆盖研究对象、主模型、关键算法。
- 摘要收尾不要空泛，可落到模型优缺点、创新点或推广价值。
- 如果采用组合模型，摘要中至少补一句“各模块分别负责什么、改进了什么”。
- 如果是链式建模，摘要里最好显式写出“中间层结果如何接到最终决策层”。

### 禁用表达
- “本文建立了若干模型并进行了求解。”
- “结果较好，说明模型有效。”
- “本文具有一定参考价值。”

## 三、问题重述模板

> 题目要求围绕【对象】解决【核心任务】，本质上需要回答以下几个问题：
> 1. 【子问题 1】
> 2. 【子问题 2】
> 3. 【子问题 3】
> 因此，本文的关键在于将实际场景中的【资源/指标/过程】转化为可度量的变量、目标函数与约束条件。

### 写作补充规则
- 问题重述尽量用自己的话改写，不直接复述题面原句。
- 重点交代背景、任务、约束和研究对象，不急着写结论。
- 篇幅通常控制在半页到 1 页，更适合做“读者快速进入题目”的引导。

## 四、模型假设模板

> 为便于建模并保证问题主干不失真，提出如下假设：
> 1. 在研究周期内，【变量】不受【可忽略因素】影响。
> 2. 已知数据来源真实可靠，且经预处理后可用于模型分析。
> 3. 若无特殊说明，默认【对象/系统】满足【基本规律】。
>
> 上述假设的作用在于降低次要干扰，突出题目关注的主要机制，而不改变问题本质。

### 使用原则
- 每个假设都要说明为什么需要。
- 尽量说明合理性依据和它对模型求解的影响。
- 不要写“为了简化模型，假设一切理想”。

## 六、模型建立模板

### 评价类
> 为综合衡量【对象】在【目标】上的表现，本文从【维度 1】、【维度 2】、【维度 3】构建指标体系。在完成指标正向化与无量纲化处理后，采用【AHP/熵权法】确定指标权重，再利用【TOPSIS/模糊综合评价/DEA】得到综合评价值与排序结果。

### 预测类
> 针对【变量】的未来变化趋势，本文首先分析其历史序列特征，判断其属于【趋势型/周期型/不规则型】。在此基础上，选用【模型】建立预测模型，并通过【误差指标】评估预测效果。

### 优化类
> 为实现【最小化/最大化目标】，设决策变量为【变量集合】，目标函数为【目标表达】。结合题目中的【资源/容量/时间/路径】等约束，构建如下优化模型，并采用【精确算法/智能优化算法】求解最优方案。

### 机理分析类
> 根据【物理/生物/经济】机制，变量【A】与【B】之间满足【规律】。据此建立【微分方程/差分方程/递推方程】描述系统演化过程，再结合初始条件和边界条件求解。

### C 题链式建模模板
> 针对【业务问题】，本文采用分层建模思路。首先对原始数据进行【缺失值处理/异常值剔除/标准化/PCA 降维】；随后建立【聚类/分类/预测】模型，得到【评分结果/需求预测/风险识别结果】；最后将该结果作为输入，构建【动态规划/多目标规划/鲁棒优化】模型，输出【补货/定价/配置/种植】方案。考虑到外部环境存在【价格波动/需求不确定/运输损耗】等干扰因素，进一步通过【蒙特卡洛/情景分析】检验方案稳健性。

### 组合模型写法模板
> 针对单一模型在【短板】上的不足，本文采用“【模型 1】+【模型 2】”的组合思路。其中，【模型 1】负责【主任务】，用于刻画【结构/趋势/权重/全局搜索】；【模型 2】负责【补充任务】，用于实现【残差修正/排序决策/局部精修/稳健增强】。这样既保留了主模型的可解释性，又弥补了其在【具体短板】上的不足。

### 参数优化型组合写法模板
> 对于【随机森林 / XGBoost / SVM】这类主模型，本文进一步引入【GA / 贝叶斯优化 / 网格搜索】进行超参数搜索。其中，主模型负责完成【预测 / 分类 / 评分】任务，优化器负责寻找更优参数组合，从而提升模型在【误差 / 泛化 / 稳定性】方面的表现。

### 深度学习稳定性写法模板
> 考虑到【LSTM / GRU / Transformer】训练过程对参数设置较为敏感，本文在建模时进一步控制【学习率策略】、【Dropout / L2 正则】、【梯度裁剪】及【初始化或 Batch Normalization】等关键因素，并结合测试集指标评估模型效果，以保证结论不是偶然跑通得到的。

### 逻辑约束写法模板
> 对于题目中的【互斥 / 启停 / 固定费用 / 指派】逻辑，本文引入 0-1 变量描述“是否执行某动作”的离散选择，并在必要时使用大 M 约束将逻辑条件转写为可求解的线性约束，从而保证模型既可计算，又保留现实业务含义。

### 链式决策写法模板
> 本文不是将各子问题孤立处理，而是构建“数据层—中间层—决策层”的链式框架。首先通过【预处理/分类/评分/预测】获得中间层结果，再将其作为后续【优化/调度/风险分级/治理方案】的输入，从而形成完整决策闭环。

### 写作结构补充
- “模型建立”宜和“模型求解”分开写，避免原理、公式、结果混成一段。
- 如果是多问题目，可按“问题一模型建立与求解—问题二模型建立与求解”展开。
- 预处理不是配角时，可单列“数据预处理”小节，再进入主模型。
- 组合模型应单独交代各模块职责、删除某模块会损失什么能力，以及是否相对基础模型有明确改进。
- 参数优化型组合应明确写成“主模型 + 超参数优化器”，不要误写成双主模型并列创新。
- 若使用深度学习，应单独补训练稳定性控制和测试评估说明。
- 链式建模要明确写出“中间层输出 → 决策层输入”的衔接句，避免前后断链。

## 七、算法设计模板

> 模型求解流程如下：
> 1. 对原始数据进行【清洗/标准化/编码/降维】；
> 2. 初始化【参数/种群/权重】；
> 3. 按照【核心迭代规则】更新变量；
> 4. 当满足【终止条件】时输出结果；
> 5. 通过【误差分析/稳定性分析】检验求解效果。

### 代码模板型写法补充
- TOPSIS：正向化 → 标准化 → 理想解距离 → 贴近度排序
- 熵权法：标准化 → 占比矩阵 → 熵值 → 权重
- PCA：标准化 → 提取主成分 → 累计解释方差判断保留维度
- 随机森林：训练/测试拆分 → 训练 → 评估 → 特征重要性解释
- PSO：初始化 → 个体最优/全局最优更新 → 迭代搜索 → 输出近优解
- Logistic 微分方程：建立方程 → 给定初值与参数 → 数值求解 → 解释长期稳定状态
- 遗传算法：编码设计 → 适应度函数 → 选择/交叉/变异 → 迭代更新 → 输出近优方案
- 整数规划：定义 0-1 / 整数变量 → 写目标函数与约束 → 求解器求最优方案 → 检查可行性与约束满足

### 高分补充句
- “考虑到目标函数存在非凸性，本文采用智能优化算法搜索近优解。”
- “考虑到变量取值受整数约束，本文采用整数规划而非连续优化方法。”
- “考虑到原始特征维度较高，本文先通过 PCA 压缩冗余信息，再进入后续预测与决策模型。”
- “考虑到基础模型在【短板】上存在不足，本文进一步引入【模型】进行补充修正，并通过对照检验证明改进有效。”
- “对于 RF + GA、XGBoost + 贝叶斯优化这类方案，本文更稳妥地写成‘主模型 + 超参数优化器’，避免把调参过程误写成双主模型创新。”
- “对于 LSTM / GRU 等深度学习模型，本文额外交代训练稳定性控制与测试集表现，以证明结果具有可重复性与可信度。”
- “对于 0-1 变量与大 M 约束，本文同步说明其对应的现实动作与逻辑条件，避免模型只有公式而没有业务含义。”

## 八、结果分析模板

> 由模型求解结果可知，【核心现象】。这说明在【条件】下，【变量】对【目标】具有显著影响。从实际意义看，【结果】意味着【管理/工程/政策解释】。进一步比较不同情景下的结果发现，【对比结论】。

### C 题结果分析补充模板
> 中间层结果表明，【分类/评分/预测】模型能够识别出【关键模式】；在此基础上，决策层模型进一步给出了【补货/定价/配置/种植】方案。相比基准方案，改进方案在【收益/成本/风险/周转率】上表现为【提升或下降幅度】。进一步在【价格波动/需求变化】情景下测试发现，该方案仍保持【稳定性结论】。

### 组合模型结果分析补充模板
> 组合模型结果表明，【模型 1】有效刻画了【主结构】，而【模型 2】进一步改善了【残差/排序差异/局部搜索效果】。与基础模型相比，改进方案在【误差/收益/排序稳定性】上具有更优表现，说明组合策略确实补足了单模型的真实短板。

### 禁用表达
- “结果如表所示。”
- “由图可知模型很好。”
- “结果基本符合实际。”
- “该方案较优。”
- “模型有效。”

## 十、模型检验写作模板

### 1. 通用总起句
> 为验证模型结果的可靠性，本文进一步从【误差表现 / 参数扰动 / 情景变化 / 样本划分】等角度对模型进行检验，以说明结论并非仅在当前数据条件下成立。

### 2. 评价类检验模板
> 为检验评价结果的稳定性，本文对关键权重进行【±10%】扰动，并将排序结果与【替代方法】进行比较。结果表明，核心排序结论基本保持一致，说明评价模型具有较好的稳健性。

### 3. 预测类检验模板
> 为评估预测模型的有效性，本文采用【MAE / RMSE / MAPE】作为误差指标，并对残差序列进行【白噪声 / 平稳性】检验。结果表明模型预测误差处于合理范围内，且残差不存在明显结构性规律。

### 4. 回归/统计分析类检验模板
> 为保证统计结论的可靠性，本文对模型进行了显著性检验、残差诊断与共线性检验。结果显示，核心变量在【显著性水平】下显著，且模型不存在严重共线性问题，说明回归结果具有较好的解释力。

### 5. 优化类检验模板
> 为考察方案的稳定性，本文对【需求 / 成本 / 容量】等关键参数进行情景分析与灵敏度分析。结果表明，在参数发生合理波动时，最优方案结构保持基本稳定，说明模型具有较好的鲁棒性。

### 6. 聚类/分类类检验模板
> 为检验识别效果，本文采用【准确率 / 召回率 / F1 / AUC / 轮廓系数】等指标对模型进行评估。结果表明，该模型能够较好地区分不同类别/群组，并具有一定稳定性。

### 7. 机理分析类检验模板
> 为验证机理模型的合理性，本文将模拟结果与【历史数据 / 已知规律】进行对比，并对关键参数进行扰动分析。结果表明模型能够较好地刻画系统演化趋势，且结论对参数变化不过度敏感。

### 8. 组合模型检验模板
> 为证明组合模型改进有效，本文将其与基础模型进行对照，比较【误差 / 排序稳定性 / 方案收益 / 收敛表现】等关键指标。结果表明，组合模型在【方面】上具有明确改进，说明该组合并非单纯增加复杂度。

## 十三、答辩表达模板

### 开场模板
> 各位老师好，我们的工作主要围绕题目中的【核心对象】展开。我们的总体思路是：先完成问题抽象，再根据题型选择合适模型，最后通过结果分析和稳健性检验验证方案有效性。

### 回答“为什么选这个模型”
> 我们选择【模型】的原因有三点：第一，题目本质上属于【题型】；第二，数据和约束条件与该模型的适用前提一致；第三，相比【替代方法】，该模型在【解释性/求解效率/贴题性】方面更合适。

### 回答“创新点在哪里”
> 我们的创新不在于单纯叠加复杂算法，而在于：一是对【问题】进行了更贴题的抽象；二是在模型中加入了【关键约束/参数改进】；三是通过【结果分析/稳健性分析】增强了模型的可解释性。
