# outputs/table_templates.md

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 用于把数学建模论文中的高频表格沉淀成“表名—用途—字段—放置位置—正文写法—常见风险”的表格模板库。

---

## 一、统一表格生产入口

本文件负责把字段、参数、模型结果、检验结果和答辩核心数字整理成可核对表格。表格必须服务于论文结论与代码复现，接入统一主链路：

**任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌**

推荐调用顺序：
1. 先用 `outputs/data_cleaning_standards.md` 固定字段名、单位、指标方向和清洗动作。
2. 用 `outputs/method_matching.md` 和 `outputs/algorithm_templates.md` 明确每张表服务哪个模型环节。
3. 用本文件生成符号表、参数表、结果表、检验表、对比表和答辩速查表。
4. 用 `outputs/table_result_alignment_workflow.md` 核对论文正文、摘要、图示、PPT 和代码输出中的数字是否一致。
5. 提交前用 `outputs/final_quality_gate.md` 检查关键数字是否可追溯到真实数据或真实输出文件。

表格中的每个核心数字都应能追溯到：原始字段/参数来源 → 处理代码或计算公式 → 输出文件 → 论文位置。无法追溯时必须标注【待补】或【需复核】，不得用表格制造“看似完整”的假结果。

---

## 二、总原则

1. 表格的任务是承载关键信息，不是把正文改成网格。
2. 每张表都要回答三个问题：
   - 这张表支撑哪一句核心结论？
   - 读者看完后能直接比较什么？
   - 若删掉这张表，论文会少掉什么证据？
3. 论文表与答辩表可以同源，但密度不同：
   - 论文表更完整
   - 答辩表更压缩
4. 同一张表最好只完成一个主任务：说明结果、说明参数、说明检验或说明对比。

## 二、统一模板字段

后续设计每张表时，尽量统一写出：
- **表名**
- **用途**
- **适用场景**
- **建议字段**
- **建议放置位置**
- **正文前置句**
- **表后解释句**
- **常见风险**

## 三、核心表格模板

### 模板 1：符号说明表
- **表名**：符号说明表
- **用途**：统一全文变量、参数和目标函数记号
- **适用场景**：全部题型
- **建议字段**：符号、含义、单位/约束
- **建议放置位置**：模型假设后、模型建立前
- **正文前置句**：
  - “为便于后续模型表述，先给出本文主要符号说明如下。”
- **表后解释句**：
  - “后续模型中若无特殊说明，均沿用表中的符号定义。”
- **常见风险**：
  - 符号表与正文记号不一致
  - 变量没有单位或取值范围说明

### 模板 2：参数设定表
- **表名**：参数设定与来源表
- **用途**：交代关键参数取值及依据
- **适用场景**：优化、仿真、预测、机理模型
- **建议字段**：参数、含义、取值、来源/依据
- **建议放置位置**：模型求解前或附录
- **正文前置句**：
  - “模型中的关键参数及其来源整理如表所示。”
- **表后解释句**：
  - “其中最敏感的参数为【参数名】，后文将通过灵敏度分析检验其影响。”
- **常见风险**：
  - 只给参数值，不交代来源
  - 经验参数没有配套检验说明

### 模板 3：核心结果表
- **表名**：核心结果汇总表
- **用途**：压缩呈现最关键指标、方案或结论
- **适用场景**：全部题型
- **建议字段**：指标/方案、数值、单位、结论说明、对应结果文件
- **建议放置位置**：结果分析开头或结尾
- **正文前置句**：
  - “为便于快速对照全文主结论，先汇总核心结果如下。”
- **表后解释句**：
  - “该表不是简单报数，而是用于固定全文最关键的结论锚点。”
- **常见风险**：
  - 指标太多导致重点淹没
  - 表中数字与摘要、正文不一致

### 模板 4：模型检验表
- **表名**：模型检验与稳健性结果表
- **用途**：集中展示误差、交叉验证、灵敏度或情景分析结果
- **适用场景**：全部题型
- **建议字段**：检验类型、指标、结果、结论
- **建议放置位置**：模型检验部分
- **正文前置句**：
  - “为验证模型结论的可靠性，进一步从以下几个角度进行检验。”
- **表后解释句**：
  - “由表可见，关键结论在合理扰动范围内保持稳定，说明模型具有基本可信度。”
- **常见风险**：
  - 只列指标，不给结论
  - 检验方法和题型不匹配

### 模板 5：方案对比表
- **表名**：方案/模型对比表
- **用途**：说明改进方案相对基线方案的优势
- **适用场景**：组合模型、优化题、改进模型
- **建议字段**：方法/方案、基准结果、改进结果、优势说明
- **建议放置位置**：结果分析或创新点部分
- **正文前置句**：
  - “为证明改进不是单纯增加复杂度，现将其与基准方案进行对比。”
- **表后解释句**：
  - “对比结果表明，新增模块真正改善了【误差/收益/稳定性】。”
- **常见风险**：
  - 没有明确基准对象
  - 只比一个指标，无法说明综合提升

### 模板 6：灵敏度分析表
- **表名**：关键参数灵敏度分析表
- **用途**：说明参数扰动对结果的影响范围
- **适用场景**：优化、仿真、评价、预测
- **建议字段**：参数、扰动区间、结果变化、稳定性结论
- **建议放置位置**：模型检验部分
- **正文前置句**：
  - “考虑到【参数】可能存在设定误差，本文进一步进行灵敏度分析。”
- **表后解释句**：
  - “在所设扰动区间内，核心结论变化有限，说明模型对该参数不过度敏感。”
- **常见风险**：
  - 扰动区间没有业务含义
  - 只给变化值，不解释是否还能接受

### 模板 7：群体统计表
- **表名**：群体最优方案统计表 / 分组统计表
- **用途**：把样本级方案提升为群体规律
- **适用场景**：优化题、分层决策题、治理建议题
- **建议字段**：统计对象、数值、单位、解释
- **建议放置位置**：结果分析或政策建议部分
- **正文前置句**：
  - “在个体样本方案之外，进一步汇总群体层面的总体规律。”
- **表后解释句**：
  - “该表说明结论不是个别样本偶然现象，而能沉淀为可复述的总体规律。”
- **常见风险**：
  - 只有个体结果，没有群体规律
  - 统计口径未说明

### 模板 8：答辩压缩表
- **表名**：答辩核心数字速查表
- **用途**：供答辩时快速锁定必须一致的关键数字
- **适用场景**：答辩准备、终检
- **建议字段**：数字项、数值、出处、答辩口径
- **建议放置位置**：提交包或答辩附录
- **正文前置句**：
  - 不建议放入论文正文，主要服务答辩与终检
- **表后解释句**：
  - “答辩时所有高频追问应优先对齐本表中的关键数字与解释口径。”
- **常见风险**：
  - 论文、PPT、口头答辩数字不一致
  - 只记数字，不记其业务含义

## 四、按题型推荐优先表格

### 1. 评价题
优先：
- 指标说明表
- 权重与排序结果表
- 稳健性扰动表
- 方法对比表

### 2. 预测题
优先：
- 训练/测试误差表
- 多模型对比表
- 关键时间点预测值表
- 残差诊断表

### 3. 优化题
优先：
- 参数设定表
- 约束说明表
- 样本方案表
- 群体规律统计表
- 情景分析表

### 4. 机理/仿真题
优先：
- 参数来源表
- 初始条件表
- 仿真结果表
- 扰动响应表

### 5. 链式建模题
优先：
- 中间层输出表
- 决策层输入表
- 方案对比表
- 闭环检验表

---

## 五、论文中的表格写法规则

1. 表前一句要说明“为什么给这张表”。
2. 表后至少一句要解释“读出什么结论”。
3. 表格字段命名要与正文、代码输出保持一致。
4. 能用 4 列说清的，不要做成 8 列。
5. 若表格数字很多，优先高亮最关键结论，而不是全量堆砌。
6. 表格里出现的关键数字必须同步进入摘要、答辩或终检清单。

---

## 六、终检红线

- 表题、图题、正文引用编号不一致
- 表格字段和代码输出字段对不上
- 参数无来源、结果无出处、检验无结论
- 摘要、正文、PPT 中关键数字不一致
- 只给表，不写解释
