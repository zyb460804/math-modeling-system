### 卡片 1
- **文件路径**：`数学建模国赛速成资料汇总！/SW03：2024黄金算法匹配表.pdf`
- **文件类别**：方法算法类 / 题型-方法匹配表
- **核心结论**：建模时应先判断题型与数据特征，再选模型；评价、预测、优化、预处理、相关性分析、聚类、图论、微分方程都有较清晰的高频匹配关系。
- **适用题型**：评价类、预测类、优化类、数据预处理类、聚类类、图与网络类、机理分析类
- **可复用模型/算法**：
  - 评价类：AHP、熵权法、灰色关联分析、TOPSIS、模糊综合评价、神经网络、DEA、秩和比
  - 预测类：Logistic、灰色预测、二次指数平滑、ARMA、季节指数、BP 神经网络、马尔可夫、回归分析
  - 优化类：线性规划、整数/0-1规划、动态优化、非线性规划、多目标规划、PSO、GA、模拟退火、梯度法
  - 预处理：插值、3σ、箱线图、标准化、编码、离散化、PCA/T-SNE/UMAP
  - 图论：Dijkstra、Floyd、TSP
- **可复用表达**：
  - “先依据题目目标、数据结构与约束类型判定题型，再选择与之匹配的基础模型。”
  - “若目标函数或约束均为线性，则优先考虑线性规划；若变量受整数或 0-1 限制，则转入整数规划。”
  - “当评价问题存在已知指标权重或需要基于优劣解排序时，TOPSIS 通常比层次分析法更合适。”
- **关键假设与前提**：
  - AHP 更适合无数据支撑的主观赋权场景。
  - 熵权法要求有可量化数据支撑。
  - DEA 适用于多投入多产出的效率评价。
  - Logistic 更适合单调增长趋势，马尔可夫要求“未来仅与当前状态有关”。
  - 梯度法适用于凸问题，智能优化更适合非凸问题。
- **关键推导/求解步骤**：
  1. 先识别问题属于评价、预测、优化还是机理分析。
  2. 再判断数据类型：是否有训练数据、是否时间序列、是否多指标、是否多约束。
  3. 最后根据目标函数形态、决策变量类型和解释需求选择模型与求解算法。
- **常见风险/禁忌**：
  - 把“会写某算法”误当成“适合本题”。
  - 评价问题中乱用神经网络而不说明训练数据来源。
  - 优化问题不区分凸/非凸、连续/离散变量就直接套 GA/PSO。
  - 预测问题不区分趋势型、周期型、不规则型时间序列。
- **对数学建模竞赛的直接启发**：这是构建 `method_matching.md` 的核心基础材料，特别适合做“题型—模型—算法—风险”对照表。

- **关键假设与前提**：
  - 摘要必须独立成文，不能写成目录式流水账。

  - 摘要只写“本文建立了模型”，不写结果和结论。
  - 论文只讲算法，不讲问题抽象逻辑。
  - 图表多但没有文字解释结论。
  - 优缺点和结论写成套话。

## 第一批可直接复用的规则

1. **先题型，后模型。** 不能先想算法，再回头找题目理由。
2. **先基础模型，后创新改进。** 创新优先体现在约束补充、参数优化、模型联动与现实解释，不是盲目叠加复杂算法。
3. **优化类是国赛绝对高频。** 规划模型、GA、PSO、模拟退火、多目标优化必须熟。
4. **摘要必须写结果。** 不能只写“建立模型”，必须写“得到什么结果、结论说明什么”。
5. **论文必须闭环。** 问题理解 → 假设 → 符号 → 建模 → 求解 → 结果 → 检验 → 优缺点 → 结论，缺一项就容易掉分。
6. **模型检验不能缺位。** 敏感性、稳健性、误差分析至少要有一项明确展开。
7. **选题要匹配团队。** A 题偏机理与推导，B 题偏开放与综合，C 题偏数据与经管。
8. **优秀论文的核心价值在结构与表达，不只是用了什么算法。**
9. **参数优化型组合要写清主从关系。** RF+GA、XGBoost+贝叶斯优化这类更稳妥的表达是“预测主模型 + 超参数优化器”，而不是两个主模型并列创新。
10. **深度学习能不能上，先看稳定性说明能不能补齐。** 若使用 LSTM / GRU，至少要交代学习率、正则化或 Dropout、梯度裁剪、Batch Normalization / 初始化等训练控制。
11. **出现互斥、启停、固定费用时，要优先想到 0-1 变量和大 M 约束。** 重点不只是会写公式，而是要把业务动作和逻辑条件翻译进模型。
12. **高分样本最值得学的是结构与闭环。** 先抽摘要、模型分工、结果分析、检验和创新表达，再决定是否借鉴具体模型路线。
13. **代码模板要升级成说明书再用。** 赛中真正有价值的不是“会跑代码”，而是知道模板的输入输出、参数边界、论文写法和答辩口径。
14. **题型路线最好压缩成‘题面信号 → 主路线 → 最小检验包 → 写作落点’。** 这样才适合高压赛中快速调用。
15. **最强版不是继续堆文件，而是把母库、样本库、路线库、代码说明书和冲刺库真正串起来。** 只有能从审题一路跳到写作、检验、改稿、答辩，知识库才算成体系。

  4. 在末端建立优化决策模型并加入不确定性检验。
- **常见风险/禁忌**：
  - 只做数据分析，不落到决策模型。
  - 只做预测，不把预测结果接入补货、配置、策略优化。

### 卡片 6
- **文件路径**：`14种国赛必备算法Matlab和Python源代码/14种国赛必备算法Python源代码/评价类 - TOPSIS 法.py`
- **文件类别**：代码模板类 / 评价模型模板
- **核心结论**：TOPSIS 的最小可复用实现非常清晰：正负向指标统一处理后，用到正理想解和负理想解的距离来计算贴近度并排序。
- **适用题型**：评价类、排序类、多指标优选类
- **可复用模型/算法**：极差标准化、负向指标转正、理想解距离、贴近度计算
- **可复用表达**：
  - “在完成指标正向化与无量纲化后，采用 TOPSIS 计算各方案到正负理想解的距离，并据此得到综合贴近度排序。”
- **关键假设与前提**：
  - 指标方向必须先统一。
  - 各指标尺度差异需要先消除。
  - 若要用于正式论文，通常还需补权重来源。
- **关键推导/求解步骤**：
  1. 极差标准化。
  2. 负向指标正向化。
  3. 计算正理想解和负理想解。
  4. 计算到两类理想解的欧氏距离。
  5. 计算贴近度并排序。
- **常见风险/禁忌**：
  - 直接拿原始数据算距离。
  - 负向指标不转正。
  - 排序出来后不解释方案差异原因。
- **对数学建模竞赛的直接启发**：适合作为 `04_代码模板/` 中评价类的最基础模板，也适合在论文中作为“评价模块”的标准写法底稿。

### 卡片 7
- **文件路径**：`14种国赛必备算法Matlab和Python源代码/14种国赛必备算法Python源代码/评价类 - 熵权法.py`
- **文件类别**：代码模板类 / 评价赋权模板
- **核心结论**：熵权法模板体现了客观赋权的标准流程：标准化、正向化、按列求占比、算熵值、再转成权重。
- **适用题型**：有数据支撑的评价类、指标客观赋权类
- **可复用模型/算法**：极差标准化、熵值计算、客观权重计算
- **可复用表达**：
  - “考虑到各指标具有客观观测数据，本文采用熵权法确定指标权重，以减少主观赋权偏差。”
- **关键假设与前提**：
  - 数据列必须有有效差异，否则权重没有区分度。
  - 仍需先完成负向指标正向化。
- **关键推导/求解步骤**：
  1. 标准化与正向化。
  2. 计算各方案在每个指标上的占比。
  3. 计算信息熵。
  4. 根据熵冗余度得到权重。
- **常见风险/禁忌**：

## 第三批可直接复用的规则

1. **算法索引只能帮助缩小候选范围，不能替代题型识别。** 任何算法都要先经过“目标—变量—约束—数据”四步匹配。
2. **离散组合优化优先考虑编码与可行性。** 遗传算法、蚁群算法这类启发式方法的关键不是名字，而是编码设计、适应度定义和约束处理。
3. **时间序列预测要先判断结构，再选工具。** 趋势型、季节型、短样本、小样本各有不同基线，不应把 Prophet、ARIMA、灰色预测混成同一路线。
4. **图表是结果表达工具，不是模型创新点。** 图表必须直接服务结论、比较或机制解释。
5. **启发式优化只能声称“近优”或“较优”。** 若未做严格证明，不要在论文中轻率宣称“全局最优”。

## 第四批可直接复用的规则

1. **模糊、等级、满意度问题优先考虑“评价边界是否清楚”。** 若边界本身模糊，模糊综合评价往往比硬打分更合理。
2. **离散决策题先想整数规划，不要先想智能算法。** 只有当规模、非凸性或求解复杂度确实成为瓶颈时，再考虑 GA、TS 等启发式方法。
3. **预测组合模型必须按结构分工解释。** 线性、季节、波动、非线性、状态转移分别由谁负责，必须讲清。
4. **评价类创新重点在补权重、补排序、补效率、补分层。** 不是把更多模型名字堆上去。
5. **优化类创新重点在补搜索与补约束。** 全局搜索、局部精修、精确建模、邻域优化这些职责必须一一对应。
6. **优秀案例最值得学的是“链条完整”。** 统计检验、预处理、中间模型、最终决策或评价要形成闭环，而不是只抄最后一个模型名。
7. **赛中优先保证基础模型闭环，再考虑算法升级与图表包装。**
8. **组合模型若没有基础模型对照，就很难证明改进有效。** 复杂度上升本身不能当成创新证据。
9. **图表的高分价值在于解释趋势、差异和结构，不在于炫。** 图后必须补一句结论与决策含义。
10. **摘要与结果分析都要把“中间层结果如何服务最终方案”写明。** 尤其是链式建模和 C 题场景。
11. **链式建模若没有写清输入输出衔接，应视为主线未闭环。** 只说“形成闭环”但没有说明中间层怎样进入目标函数、约束或优先级规则，仍属于高风险写法。
12. **组合模型提分的前提是“职责清楚 + 对照充分 + 收益可解释”。** 缺任何一项，都容易从“创新”变成“堆砌”。

## 第五批可直接复用的规则

1. **目录型资料最适合做“导航层”，不适合直接当理论层。** `SW01` 和 `SW02` 这种文件的价值在于帮你快速定位模板和样本。
2. **代码模板库要按任务类型管理。** 最稳的组织方式是“评价/预测/优化/图论/预处理/机理”，而不是按资料来源堆文件夹。
3. **优秀论文应按模型家族对标。** 先找同类模型的高分样本，再学其摘要、问题分析、图表组织和结果解释。
4. **评价类组合创新的本质是互补分工。** 赋权、排序、效率、分层、不确定性处理应由不同模块承担，不要重复劳动。
5. **预测类组合创新的本质是结构拆分。** 线性趋势、季节项、非线性残差、状态转移、噪声分离和波动聚集，应分别匹配对应工具。
6. **优化类组合创新的本质是先建模再求解。** 先确认变量与约束，再决定要不要引入启发式算法，不能反过来。
7. **离散决策问题优先写清 0-1/整数表达。** 启发式算法只能补搜索，不能替代逻辑约束的清晰表达。
8. **摘要最稳妥的写法仍是“总述 + 分问 + 升华”。** 总述交代题目与总路线，分问交代每问方法与结果，升华交代优缺点、推广和创新。
9. **问题重述必须改写。** 这是写作底线，不只是查重问题，更关系到是否真正理解题目。
10. **问题分析最好承担“桥梁”作用。** 这一节的价值在于解释为什么这样建模，而不是提前把结论说完。
11. **模型检验必须单列并明确类型。** 稳定性、敏感性、误差分析、统计检验、新旧模型对比，至少要有清楚展开。
12. **AI 使用应可说明。** 如果论文真实使用了 AI 工具辅助生成内容，后续提交与答辩口径里最好准备好标注与解释方案。
