# 最终质量门

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

## 用途
用于交稿前最后一轮放行检查，重点防止匿名违规、格式缺项、结果不可复现、图表正文不一致、AI 使用说明缺失、demo 结果冒充真实结论等可避免扣分问题。

- `outputs/final_quality_gate_workflow.md`

## 一、使用顺序
1. 先区分检查对象：系统层 / 案例层 / 两者都查。
2. 再判定当前模式：`demo` / `real_case`。
3. 先查 P0 阻断项。
4. 再查论文、代码、图表、表格、答辩、提交包。
5. 最后查表达、格式、匿名和 AI 使用说明。
6. 任何 P0 未通过，都不要宣称“可提交 / 可答辩 / 可复现”。

## 二、四层放行口径
| 层级 | 判断问题 | 通过标准 | 不通过后果 |
|---|---|---|---|
| 文件层 | 文件是否齐全 | 论文、代码、图表、表格、说明齐全 | 不能提交完整包 |
| 运行层 | 代码是否能跑 | 主链路能生成核心输出 | 不能宣称可复现 |
| 真实性层 | 结果是否真实 | 关键数字来自真实数据和真实求解 | 不能按 `real_case` 通过 |
| 表达层 | 论文和答辩是否一致 | 数字、结论、图表、口径统一 | 答辩和审稿高风险 |

## 二点五、作品目录受控规则（v4.5 新增）

> **背景（2026-08 实测教训）**：B 题作品放在桌面"测试"目录，系统门禁脚本硬编码 `paper_output/`，导致证据门、代码自证门、数字一致性全部落空，空表格/空结果文件/编造公式带病交付。

1. **唯一受控工作区**：正式作品的论文、代码、结果、图表必须统一建在 `paper_output/`（或其子目录）下；题目与附件放入 `problem_files/<题号>/`。
2. **目录漂移即 FAIL**：若作品文件散落在系统外（桌面、临时目录等），终检时必须以该目录为 `--paper-dir` 运行实物门，并在报告中登记"作品目录漂移"为 P1 风险。
3. **一键终检总门**：任何最终稿（real_case）在宣称"可提交/可答辩/可复现"前，必须运行：
   `python tools/quality_gate/final_gate_runner.py --paper-dir <作品目录> --workdir E:/数学建模`
   全部 ✅ PASS 才允许进入提交包生成；任一 ❌ FAIL 即阻断。
4. **结果文件硬性要求**：题目要求"结果保存到 xxx.xlsx/xxx.csv"时，该文件必须在作品目录内且数据区非空（由实物门自动校验，纯表头判为空）。

## 二点六、G4.7 实物门（Artifact Gate，v4.5 新增）

**为什么加这道门**：原证据门只检查 `paper_output` 下的 JSON 索引是否存在，不检查最终交付物实物。实测作品 `final_paper.docx` 表格实体为 0、`result1/result2.xlsx` 只有表头，证据门全部 PASS，纸面门禁形同虚设。

**检查内容**（`tools/quality_gate/paper_artifact_check.py`，支持任意 `--paper-dir`）：
| 检查项 | 通过标准 |
|---|---|
| 论文 docx 存在 | 作品目录内有非备份 docx |
| 表格实体 | docx 内 `<w:tbl>` 实体数 ≥ 1；题面要求的结果表/符号表必须为真实表格，不得用文字占位 |
| 图片 | 计算/几何类题目建议 ≥ 2 张图（warning 级） |
| 占位残留 | 正文不得残留【待补】/TODO/**表1 占位/**如下表所示：** 等模板标记 |
| 结果 xlsx | result*.xlsx 排除表头后数据区非空（纯表头判为空 = FAIL） |
| 代码存在 | 作品目录内有 .py/.m/.R 代码文件（否则不可复现 = FAIL） |

**退出码**：0 = PASS；1 = FAIL（存在任一 failures）。

## 二点七、G4.8 数字一致性客观核对（v4.5 升级）

- 原 `check_number_consistency.py` 为单题定制（A 题电网指标写死），换题即失效 → 升级为通用模式：从论文 docx 提取全部数字，与作品目录 `results/*.json|*.csv` 的数字集合对比，报告"论文出现但结果文件无来源"的数字。
- **结果文件缺失 = FAIL（P0）**：论文关键数字无法客观溯源时，不得宣称可复现。
- 通用检查存在误报（公式系数、页码等），命中项进入 warning 人工复核，但"无结果文件"直接阻断。

## 二点八、G4.9 公式核验门（v4.5 新增）

**为什么加这道门**：实测 Q2 方向修正系数 k=0.3 系凭空设定，Q1 覆盖宽度公式为非标准近似式——系统原 G2 只验证"PoC 能跑出数字"，不验证公式是否与官方参考答案/权威解法一致。

1. **历年真题（国赛/美赛/电工杯/五一赛等）必须做公式核验**：开工后、写公式前，用官方参考答案/权威论文（award-paper-rag、citation-tracer、网络官方源）核对每个核心公式，输出 `paper_output/plan/formula_verification.md`，每条公式记录：公式名 / 论文用式 / 官方式 / 差异与误差量级 / 来源 / 结论（一致/近似可用/必须修正）。
2. 未核验的公式不得写入正文；含【待核验】残留不得通过终检。
3. 若官方参考答案不可得（非真题/新题），在 formula_verification.md 中说明检索过程与理由，由人工确认后放行。

## 三、P0 阻断项
| 检查项 | 通过标准 | 未通过处理 |
|---|---|---|
| 匿名要求 | 论文、代码、文件名、属性中无学校、姓名、队伍等违规信息 | 立即清理并复查全文 |
| 子问题回答 | 每个子问题都有明确回答 | 回到问题分析、模型和结果部分补齐 |
| 主模型匹配 | 模型能解释题目目标、数据条件和约束 | 重新说明模型选择理由或换基础模型 |
| 变量定义 | 核心变量、参数、单位、指标方向清楚 | 补符号表、参数表、指标说明 |
| 结果来源 | 主要结果能对应公式、代码或计算过程 | 补求解过程、代码输出或表格来源 |
| 检验分析 | 至少有误差、对比、灵敏度、稳健性或约束核查之一 | 补最小可行检验 |
| 口径一致 | 论文、图表、表格、代码、答辩关键数字一致 | 建结果对表并统一数字 |
| 真实性 | 不存在 demo/fallback/占位结果冒充真实结论 | 降级为 demo 或补真实链路 |
| 结论支撑 | 摘要和结论不超出正文证据 | 删除或弱化无支撑表述 |
| AI 使用说明 | 按赛事要求说明工具、用途和人工复核 | 补 AI 使用说明 |
| 提交文件 | 论文、代码、数据/说明、AI 使用说明等按要求齐全 | 建立缺项清单并优先补齐 |

## 四、论文终检
- [ ] 标题、摘要、关键词完整。
- [ ] 摘要包含问题、方法、关键结果、结论，不只有背景介绍。
- [ ] 问题分析逐一对应题目子问题。
- [ ] 假设必要、简洁，并能服务模型。
- [ ] 符号说明覆盖主要变量、参数和单位。
- [ ] 目标函数、约束、算法流程与结果一致。
- [ ] 图表编号连续，正文均有引用。
- [ ] 公式编号、变量符号、上下标前后一致。
- [ ] 结果分析解释现实含义，不只罗列数值。
- [ ] 灵敏度、误差、对比或稳健性分析与主结论相关。
- [ ] 参考文献格式统一，引用不过度堆砌。
- [ ] 不出现明显模板痕迹、空话套话或“待补”残留。

## 五、代码与复现终检
- [ ] 有主入口或清晰运行顺序。
- [ ] 依赖库、运行环境、输入文件路径说明清楚。
- [ ] 关键参数集中在配置文件或参数区。
- [ ] 随机过程设置随机种子或说明重复试验口径。
- [ ] 输出文件名与论文表格、图表能对应。
- [ ] 代码中的变量名和论文核心变量不冲突。
- [ ] 没有硬编码绝对路径影响复现。
- [ ] 缺失数据或待补参数已明确说明。
- [ ] 不提交无关临时文件、缓存文件或测试垃圾文件。
- [ ] 核心结果能从输入数据和脚本运行链路追溯。

## 六、图表与表格终检
- [ ] 技术路线图与论文结构一致。
- [ ] 模型结构图中的变量与公式一致。
- [ ] 结果图有坐标轴、单位、图例和必要注释。
- [ ] 表格列名、单位、精度统一。
- [ ] 图表不是单纯装饰，而能支撑一个结论。
- [ ] 预测图区分历史段、预测段和真实值。
- [ ] 优化结果表能还原可执行方案。
- [ ] 灵敏度图有基准值和扰动范围。
- [ ] 论文、PPT、表格、代码输出中的关键数字一致。

## 七、AI 使用说明终检
- [ ] 说明使用了哪些 AI 工具。
- [ ] 说明 AI 参与的环节，如资料整理、代码辅助、文字润色、图表构思。
- [ ] 说明人工复核与修改内容。
- [ ] 不把 AI 生成内容直接声明为未经核验的事实。
- [ ] 与赛事官方格式要求一致。

## 八、答辩口径终检
- [ ] 能用 1 分钟讲清技术路线。
- [ ] 能回答为什么选择当前模型，而不是替代模型。
- [ ] 能解释关键参数来源。
- [ ] 能说明结果可信度来自哪些检验。
- [ ] 能承认模型局限并给出改进方向。
- [ ] 汇报 PPT 与论文结论一致。
- [ ] 危险追问有 15 秒和 40 秒两个版本回答。

## 九、提交包清单
| 文件 | 是否必须 | 检查重点 |
|---|---|---|
| 论文正文 | 必须 | 匿名、格式、结论闭环 |
| 摘要版 | 视赛事要求 | 关键结果、结论不夸大 |
| 支撑材料 | 按要求 | 数据、代码、附件命名 |
| 代码文件 | 通常必须 | 可运行、可复现、路径清楚 |
| 结果表格 | 建议 | 与论文结果一致 |
| 图表文件 | 建议 | 与正文编号一致 |
| PPT/答辩材料 | 视赛事要求 | 与论文和图表一致 |
| AI 使用说明 | 按赛事要求 | 工具、用途、人工复核 |
| 复现说明 | 建议 | 运行顺序、依赖、输入输出 |

## 十、放行结论模板
| 结论 | 判定条件 |
|---|---|
| 可冲奖稿 | P0 全过，P1 基本补齐，结果解释和检验有亮点 |
| 可提交稿 | P0 全过，核心结果完整，仍有部分 P1/P2 可优化 |
| 风险较高稿 | 存在 P0 或多个 P1，可能被扣核心分 |
| demo 骨架 | 文件或代码存在，但真实数据、真实结果或动态验收未闭合 |

## 十一、最后一小时检查顺序
1. 匿名与文件命名。
2. 摘要和结论是否有硬结果。
3. 图表、表格、公式编号是否一致。
4. 关键数字是否在论文、PPT、表格、代码输出中一致。
5. 代码是否有运行说明。
6. AI 使用说明是否齐全。
7. 压缩包或提交目录是否只包含必要文件。

## 十二、不建议最后一小时做的事
- 大换模型。
- 重写全篇结构。
- 临时加入未验证的复杂算法。
- 删除已有检验只为节省篇幅。
- 为了美观改动已核对过的结果表。
- 把不确定结果写得过满。

## 十三、通过标准
只有同时满足以下条件，才能判为 `real_case` 可提交：
1. 真实题面、真实数据、真实代码链已接入。
2. 主链路能生成核心表和图。
3. 关键数字能追溯。
4. 至少有一种可信度检验。
5. 论文、图表、表格、答辩口径一致。
6. 提交包满足赛事格式和 AI 使用要求。
7. 不再依赖 demo/fallback/占位结果冒充真实结论。
