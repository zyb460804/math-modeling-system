# 最终质量门

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

## 用途
用于交稿前最后一轮放行检查，重点防止匿名违规、格式缺项、结果不可复现、图表正文不一致、AI 使用说明缺失、demo 结果冒充真实结论等可避免扣分问题。

## 使用入口
优先配套：
- `prompts/28_final_quality_gate.md`
- `outputs/final_quality_gate_workflow.md`
- `outputs/scoring_rubric.md`
- `outputs/review_priority_matrix.md`
- `outputs/reproducibility_checklist.md`
- `outputs/validation_checklist.md`
- `outputs/table_result_alignment_workflow.md`
- `deliverables/00_系统自测清单.md`
- `deliverables/00_提交包总览与终检清单.md`

## 一、使用顺序
1. 先区分检查对象：系统层 / 案例层 / 两者都查。
2. 再判定当前模式：`demo` / `real_case`。
3. 先查 P0 阻断项。
4. 再查论文、代码、图表、表格、答辩、提交包。
5. 最后查表达、格式、匿名和 AI 使用说明。
6. 任何 P0 未通过，都不要宣称“可提交 / 可答辩 / 可复现”。

## 二、四层放行口径
| 层级 | 判断问题 | 通过标准 | 不通过后果 |
|---|---|---|---|
| 文件层 | 文件是否齐全 | 论文、代码、图表、表格、说明齐全 | 不能提交完整包 |
| 运行层 | 代码是否能跑 | 主链路能生成核心输出 | 不能宣称可复现 |
| 真实性层 | 结果是否真实 | 关键数字来自真实数据和真实求解 | 不能按 `real_case` 通过 |
| 表达层 | 论文和答辩是否一致 | 数字、结论、图表、口径统一 | 答辩和审稿高风险 |

## 三、P0 阻断项
| 检查项 | 通过标准 | 未通过处理 |
|---|---|---|
| 匿名要求 | 论文、代码、文件名、属性中无学校、姓名、队伍等违规信息 | 立即清理并复查全文 |
| 子问题回答 | 每个子问题都有明确回答 | 回到问题分析、模型和结果部分补齐 |
| 主模型匹配 | 模型能解释题目目标、数据条件和约束 | 重新说明模型选择理由或换基础模型 |
| 变量定义 | 核心变量、参数、单位、指标方向清楚 | 补符号表、参数表、指标说明 |
| 结果来源 | 主要结果能对应公式、代码或计算过程 | 补求解过程、代码输出或表格来源 |
| 检验分析 | 至少有误差、对比、灵敏度、稳健性或约束核查之一 | 补最小可行检验 |
| 口径一致 | 论文、图表、表格、代码、答辩关键数字一致 | 建结果对表并统一数字 |
| 真实性 | 不存在 demo/fallback/占位结果冒充真实结论 | 降级为 demo 或补真实链路 |
| 结论支撑 | 摘要和结论不超出正文证据 | 删除或弱化无支撑表述 |
| AI 使用说明 | 按赛事要求说明工具、用途和人工复核 | 补 AI 使用说明 |
| 提交文件 | 论文、代码、数据/说明、AI 使用说明等按要求齐全 | 建立缺项清单并优先补齐 |

## 四、论文终检
- [ ] 标题、摘要、关键词完整。
- [ ] 摘要包含问题、方法、关键结果、结论，不只有背景介绍。
- [ ] 问题分析逐一对应题目子问题。
- [ ] 假设必要、简洁，并能服务模型。
- [ ] 符号说明覆盖主要变量、参数和单位。
- [ ] 目标函数、约束、算法流程与结果一致。
- [ ] 图表编号连续，正文均有引用。
- [ ] 公式编号、变量符号、上下标前后一致。
- [ ] 结果分析解释现实含义，不只罗列数值。
- [ ] 灵敏度、误差、对比或稳健性分析与主结论相关。
- [ ] 参考文献格式统一，引用不过度堆砌。
- [ ] 不出现明显模板痕迹、空话套话或“待补”残留。

## 五、代码与复现终检
- [ ] 有主入口或清晰运行顺序。
- [ ] 依赖库、运行环境、输入文件路径说明清楚。
- [ ] 关键参数集中在配置文件或参数区。
- [ ] 随机过程设置随机种子或说明重复试验口径。
- [ ] 输出文件名与论文表格、图表能对应。
- [ ] 代码中的变量名和论文核心变量不冲突。
- [ ] 没有硬编码绝对路径影响复现。
- [ ] 缺失数据或待补参数已明确说明。
- [ ] 不提交无关临时文件、缓存文件或测试垃圾文件。
- [ ] 核心结果能从输入数据和脚本运行链路追溯。

## 六、图表与表格终检
- [ ] 技术路线图与论文结构一致。
- [ ] 模型结构图中的变量与公式一致。
- [ ] 结果图有坐标轴、单位、图例和必要注释。
- [ ] 表格列名、单位、精度统一。
- [ ] 图表不是单纯装饰，而能支撑一个结论。
- [ ] 预测图区分历史段、预测段和真实值。
- [ ] 优化结果表能还原可执行方案。
- [ ] 灵敏度图有基准值和扰动范围。
- [ ] 论文、PPT、表格、代码输出中的关键数字一致。

## 七、AI 使用说明终检
- [ ] 说明使用了哪些 AI 工具。
- [ ] 说明 AI 参与的环节，如资料整理、代码辅助、文字润色、图表构思。
- [ ] 说明人工复核与修改内容。
- [ ] 不把 AI 生成内容直接声明为未经核验的事实。
- [ ] 与赛事官方格式要求一致。

## 八、答辩口径终检
- [ ] 能用 1 分钟讲清技术路线。
- [ ] 能回答为什么选择当前模型，而不是替代模型。
- [ ] 能解释关键参数来源。
- [ ] 能说明结果可信度来自哪些检验。
- [ ] 能承认模型局限并给出改进方向。
- [ ] 汇报 PPT 与论文结论一致。
- [ ] 危险追问有 15 秒和 40 秒两个版本回答。

## 九、提交包清单
| 文件 | 是否必须 | 检查重点 |
|---|---|---|
| 论文正文 | 必须 | 匿名、格式、结论闭环 |
| 摘要版 | 视赛事要求 | 关键结果、结论不夸大 |
| 支撑材料 | 按要求 | 数据、代码、附件命名 |
| 代码文件 | 通常必须 | 可运行、可复现、路径清楚 |
| 结果表格 | 建议 | 与论文结果一致 |
| 图表文件 | 建议 | 与正文编号一致 |
| PPT/答辩材料 | 视赛事要求 | 与论文和图表一致 |
| AI 使用说明 | 按赛事要求 | 工具、用途、人工复核 |
| 复现说明 | 建议 | 运行顺序、依赖、输入输出 |

## 十、放行结论模板
| 结论 | 判定条件 |
|---|---|
| 可冲奖稿 | P0 全过，P1 基本补齐，结果解释和检验有亮点 |
| 可提交稿 | P0 全过，核心结果完整，仍有部分 P1/P2 可优化 |
| 风险较高稿 | 存在 P0 或多个 P1，可能被扣核心分 |
| demo 骨架 | 文件或代码存在，但真实数据、真实结果或动态验收未闭合 |

## 十一、最后一小时检查顺序
1. 匿名与文件命名。
2. 摘要和结论是否有硬结果。
3. 图表、表格、公式编号是否一致。
4. 关键数字是否在论文、PPT、表格、代码输出中一致。
5. 代码是否有运行说明。
6. AI 使用说明是否齐全。
7. 压缩包或提交目录是否只包含必要文件。

## 十二、不建议最后一小时做的事
- 大换模型。
- 重写全篇结构。
- 临时加入未验证的复杂算法。
- 删除已有检验只为节省篇幅。
- 为了美观改动已核对过的结果表。
- 把不确定结果写得过满。

## 十三、通过标准
只有同时满足以下条件，才能判为 `real_case` 可提交：
1. 真实题面、真实数据、真实代码链已接入。
2. 主链路能生成核心表和图。
3. 关键数字能追溯。
4. 至少有一种可信度检验。
5. 论文、图表、表格、答辩口径一致。
6. 提交包满足赛事格式和 AI 使用要求。
7. 不再依赖 demo/fallback/占位结果冒充真实结论。
