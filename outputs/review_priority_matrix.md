> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

> 用于把审稿问题按 P0 / P1 / P2 进一步细化成处理矩阵，方便最后半天快速分配改稿顺序。

---

## 一、分级原则

### P0：必须先修
特征：
- 不修会直接影响是否回应题目
- 不修会让评委怀疑论文是否成立
- 不修会在摘要、主模型、检验、结果层面出现硬伤

### P1：明显提分项
特征：
- 主体已经成立，但表达、解释、对比和闭环还不够强
- 修完后论文会从“能交”变成“更稳”

### P2：冲分优化项
特征：
- 不影响主线成立
- 主要提升精细度、观感和答辩表现

## 二、问题分级矩阵

| 问题现象 | 优先级 | 为什么 | 先怎么修 |
|---|---|---|---|
| 题型判断错误 | P0 | 主线跑偏 | 先重写问题分析与模型主线 |
| 没有目标函数/约束/变量定义 | P0 | 模型不成立 | 先补模型定义框架 |
| 摘要没有结果 | P0 | 一眼掉分 | 先补关键结果和结论 |
| 完全没有模型检验 | P0 | 可信度不足 | 先补核心检验小节 |
| 结果不能回应题目要求 | P0 | 没完成任务 | 先重构结果分析与决策输出 |
| 链式建模没有写清“中间层输出 → 决策层输入” | P0 | 论文闭环断裂 | 先补输入输出衔接和方案层使用证据 |
| 模型选择理由不清 | P1 | 容易被质疑 | 补选模逻辑与替代方法比较 |
| 结果只报数值不解释 | P1 | 论文不成闭环 | 补现象—原因—启示 |
| 没有基准方案对比 | P1 | 改进价值不明显 | 补对比分析 |
| A / B / C 题回答重心错位 | P0 | 主线虽有内容但评分口径偏了 | A 题补机理与边界，B 题补比较与建议，C 题补链式闭环 |
| 参数优化型组合写成双主模型 | P1 | 创新表达失真，容易被质疑堆模型 | 改写成“主模型 + 超参数优化器”并补调参前后对照 |
| 复杂组合模型没有说明删掉某模块会损失什么 | P1 | 职责边界不清 | 给每个模块补短板、职责和删减后影响 |
| 图表命名不规范 | P2 | 影响专业感 | 统一图表编号和标题 |
| 参考文献格式不统一 | P2 | 细节失分 | 统一格式 |

## 三、最稳妥的修改顺序

1. **先修审题与主线**
   - 先确认题型
   - 再确认每问输出
   - 最后确认模型链条

2. **再修模型成立性**
   - 变量、约束、目标函数、评价逻辑补全
   - 模型职责说清

3. **再修可信度**
   - 检验
   - 误差
   - 稳健性
   - 边界

4. **再修结果落地**
   - 排名差异解释
   - 趋势含义解释
   - 最优方案落地

5. **最后修表达与包装**
   - 摘要
   - 图表标题
   - 创新点表达
   - 答辩短答

## 四、按剩余时间倒推怎么改

### 1. 如果只剩 30 分钟
只做三件事：
- 重写摘要，写清结果
- 补一段模型检验
- 补一段结果落地建议

### 2. 如果只剩 2 小时
优先做：
- 修正题型判断和模型主线
- 补最关键模型检验
- 把结果分析从“报数”改成“解释 + 建议”
- 统一图表和符号

### 3. 如果还剩半天
优先做：
- 补对比实验或情景分析
- 优化创新点表达
- 强化答辩口径
- 修摘要与结论的一致性

## 五、不同问题的处理动作模板

### 1. 如果属于“审题跑偏”
- 先删掉错位模型的铺陈
- 再重写问题分析
- 再重排模型顺序

### 2. 如果属于“模型堆砌”
- 给每个模型写职责
- 没职责的直接删除
- 只保留主干模型和必要辅助模型
- 若是组合模型，再补基础模型对照与改进收益说明
- 若是参数优化型组合，改写成“主模型 + 超参数优化器”结构

### 3. 如果属于“A / B / C 题口径错位”
- A 题优先补机理解释、参数意义、边界条件与敏感性分析
- B 题优先补比较分析、差异来源和施策建议
- C 题优先补“预处理—中间层—决策层”闭环与输入输出衔接

### 4. 如果属于“检验缺失”
- 选当前主模型最关键的一项检验先补
- 补一项参数扰动或情景分析
- 加一句适用边界说明
- 若是链式建模，再补最终方案层检验

### 4. 如果属于“结果不落地”
- 每段结果后补一句“因此建议……”
- 把排序、预测、最优解翻译成动作
- 加一个优先顺序或关键对象判断
- 明确“中间层输出 → 最终决策动作”的衔接句

---

## 六、最容易误判优先级的情况

1. 以为“创新点不够亮”是最大问题，实际上是没检验。
2. 以为“图表不够炫”是最大问题，实际上是结果没解释。
3. 以为“模型不够复杂”是最大问题，实际上是主线不清。
4. 以为“写作不够高级”是最大问题，实际上是题型误判。

---

## 七、最稳妥的结论

当时间有限时，永远优先保证四件事：
- 题目答对了
- 模型站得住
- 结果说得清
- 检验补上了

若是链式建模或组合模型，再额外优先确认两件事：
- 中间层输出是否真的进入最终方案层
- 改进模型是否有基础模型对照

如果想从“改到能交”继续升级到“强终稿 / 强答辩稿”，再联动：
- `outputs/paper_upgrade_playbook.md`
- `outputs/winning_paper_pattern_library.md`
- `outputs/high_score_expression_library.md`

这四件事完成后，再追求创新包装和表达精修。
