## 一、总原则

1. 读图不是只看长什么样，而是识别它在表达什么逻辑。
2. 每张图至少要回答一个问题：
   - 题目结构是什么？
   - 模型怎么走？
   - 变量如何关联？
   - 算法如何推进？
   - 结果说明什么？
3. 图示应尽量服务“解释闭环”，而不是增加装饰感。
4. 一张高质量图的价值，通常高于三张无重点的炫图。

## 二、视觉材料分类体系

### 1. 题目理解图
- **常见来源**：题面截图、题目分问结构图、附件字段截图
- **主要作用**：把题目拆成目标、约束、输入、输出
- **适合沉淀为**：题目结构图、任务拆解图、题型判断图
- **更适合放在**：问题分析部分、答辩第一页或第二页

### 2. 技术路线图
- **常见来源**：论文总流程图、章节结构图、模型主线图
- **主要作用**：展示全文从数据到方案的总路径
- **适合沉淀为**：总流程图、链式建模总图、论文结构图
- **更适合放在**：模型总体思路、答辩开场

### 3. 模型结构图
- **常见来源**：变量关系图、模块结构图、系统关系图
- **主要作用**：展示模型内部由哪些部分组成、各模块如何连接
- **适合沉淀为**：系统结构图、变量作用图、模块分层图
- **更适合放在**：模型建立部分、答辩主模型说明页

### 4. 算法流程图
- **常见来源**：算法框图、伪代码截图、程序流程截图
- **主要作用**：说明算法步骤、循环逻辑、输入输出关系
- **适合沉淀为**：流程框图、迭代图、求解流程图
- **更适合放在**：算法设计部分、答辩算法解释页

### 5. 数据处理图
- **常见来源**：清洗流程图、预处理流程图、字段筛选图
- **主要作用**：说明数据如何从原始态进入模型
- **适合沉淀为**：预处理流程图、特征处理图、样本筛选图
- **更适合放在**：数据预处理部分、附录或答辩补充页

### 6. 结果展示图
- **常见来源**：趋势图、对比图、排序图、热力图、空间图
- **主要作用**：展示结论、差异、趋势、空间结构
- **适合沉淀为**：关键结果图、方案对比图、情景图
- **更适合放在**：结果分析部分、答辩核心展示页

### 7. 检验与稳健性图
- **常见来源**：残差图、灵敏度图、收敛曲线、情景分析图
- **主要作用**：证明结果不是碰巧得到的
- **适合沉淀为**：误差图、敏感性图、稳定性图
- **更适合放在**：模型检验部分、答辩可信度支撑页

### 8. 答辩压缩图
- **常见来源**：一页总结图、核心逻辑图、结论压缩图
- **主要作用**：让评委在 30–60 秒内抓住主线
- **适合沉淀为**：一图讲清全文、核心卖点图、追问应对图
- **更适合放在**：答辩开场、总结、追问说明

## 三、视觉材料“四读”提炼法

### 第一读：读对象
先识别图里有哪些对象：
- 数据
- 指标
- 变量
- 模块
- 阶段
- 结果
- 决策动作

### 第二读：读关系
再识别对象之间的关系：
- 因果关系
- 输入输出关系
- 时间顺序
- 递进关系
- 并列关系
- 反馈关系
- 约束关系

### 第三读：读用途
判断这张图真正服务什么：
- 服务问题分析
- 服务模型解释
- 服务算法说明
- 服务结果展示
- 服务可信度证明
- 服务答辩压缩表达

### 第四读：读迁移价值
最后判断能沉淀成什么模板：
- 可直接复用
- 需按题目替换节点名
- 只保留结构，不保留内容
- 不建议复用，仅作灵感参考

## 四、高频可复用视觉模板

### 模板 1：题目拆解图
- **适用场景**：多问题、链式题、C 题业务题
- **标准结构**：题目目标 → 子问题 1/2/3 → 变量与约束 → 预期输出
- **核心价值**：避免审题跑偏
- **常用标题**：
  - “题目任务拆解图”
  - “问题结构与求解目标示意图”

### 模板 2：技术路线图
- **适用场景**：几乎所有数模论文
- **标准结构**：数据 / 题目信息 → 预处理 → 主模型 → 检验 → 结果 → 建议
- **核心价值**：一图讲清全文主线
- **常用标题**：
  - “本文技术路线图”
  - “整体建模流程图”

### 模板 3：链式建模总图
- **适用场景**：预测→优化、评分→分级→决策、分类→治理
- **标准结构**：前端识别层 → 中间结果 → 决策层 → 输出方案 → 检验
- **核心价值**：避免断链
- **常用标题**：
  - “链式建模闭环结构图”
  - “中间层—决策层耦合关系图”

### 模板 4：算法流程图
- **适用场景**：GA、PSO、ACO、动态规划、复杂求解器流程
- **标准结构**：输入 → 初始化 → 迭代更新 → 终止判断 → 输出
- **核心价值**：说明算法不是黑箱
- **常用标题**：
  - “算法求解流程图”
  - “模型求解步骤示意图”

### 模板 5：变量关系图
- **适用场景**：机理分析、回归分析、系统动力学
- **标准结构**：核心变量 → 影响路径 → 中介变量 → 结果变量
- **核心价值**：帮助解释假设与机制
- **常用标题**：
  - “变量作用关系图”
  - “系统机理结构图”

### 模板 6：结果对比图组
- **适用场景**：评价、预测、优化题
- **标准结构**：基准方案 vs 改进方案 vs 情景扰动方案
- **核心价值**：让提升幅度可视化
- **常用标题**：
  - “方案对比结果图”
  - “不同情景下结果表现对比图”

### 模板 7：稳健性图
- **适用场景**：需要证明结果可信时
- **标准结构**：参数扰动 / 多次运行 / 不同情景 → 关键结果变化
- **核心价值**：证明稳定性
- **常用标题**：
  - “模型稳健性分析图”
  - “关键参数扰动结果图”

### 模板 8：答辩压缩总图
- **适用场景**：答辩 5 分钟、PPT 核心页
- **标准结构**：题目 → 主模型 → 核心结果 → 检验 → 创新点
- **核心价值**：快速建立评委理解
- **常用标题**：
  - “全文核心逻辑压缩图”
  - “模型与结果总览图”

## 五、图片到图示模板的映射规则

| 原始图片类型 | 优先提炼对象 | 推荐沉淀模板 | 使用场景 |
|---|---|---|---|
| 题面截图 | 任务、约束、输入输出 | 题目拆解图 | 审题、答辩开场 |
| 流程图截图 | 步骤、顺序、判断分支 | 技术路线图 / 算法流程图 | 模型、算法部分 |
| 算法框图 | 输入、迭代、终止条件 | 算法流程图 | 算法设计 |
| 论文结构图 | 模块层级、衔接关系 | 技术路线图 | 论文开头 |
| 表格截图 | 指标、字段、分层结构 | 指标体系图 / 数据处理图 | 问题分析、预处理 |
| 结果截图 | 趋势、差异、异常点 | 结果展示图 | 结果分析 |
| 稳健性截图 | 波动区间、误差变化 | 稳健性图 | 检验部分 |
| PPT 截图 | 压缩表达、重点顺序 | 答辩压缩总图 | 答辩 |

## 六、论文中的最佳放置位置

适合放：

### 2. 模型建立开头
适合放：
- 技术路线图

- 变量关系图

### 3. 算法设计部分
适合放：
- 算法流程图
- 求解流程图
- 数据处理流程图

### 4. 结果分析部分
适合放：
- 趋势图
- 对比图
- 排名图
- 空间图

### 5. 模型检验部分
适合放：
- 误差图
- 残差图

### 6. 答辩页
最优先放：
- 一张总流程图

## 七、高分图示的共性

1. 标题具体，不写“结果图”“流程图”这种空标题。
2. 中文标注短句化，不堆长句。
3. 层级清晰，读者一眼能看出先后和主次。
4. 图中节点数量克制，通常 5–9 个核心节点最稳。
5. 论文图和答辩图可以同源，但答辩版应更压缩。

---

## 八、常见低分图示问题

- 节点太多，像思维导图，不像论文图
- 箭头太乱，主线不清楚
- 图名空泛，没有对象和用途
- 图中术语与正文不一致
- 图有了，但正文前后没有引用和解释
- 为了好看加入过多颜色和装饰元素
- 只展示过程，不展示中间层如何进入决策层

## 九、图示配套写法模板

### 总流程图前置句
- “为清晰说明本文的整体求解主线，现给出技术路线图如下。”
- “考虑到本文涉及多阶段建模，先以流程图概括各模块的输入输出关系。”

### 图后解释句
- “该图展示了从题目输入到结果输出的完整路径，其中【中间层】是衔接前后模块的关键。”
- “需要强调的是，图中【节点】并非并列摆放，而是存在明确的输入输出传递关系。”

### 答辩压缩句
- “如果只用一张图解释全文，我会用这张图说明题目、模型、结果和检验之间的关系。”

## 十一、赛中快速判断法

看到一张图片时，先问五个问题：
1. 这张图在解释什么？
2. 它属于题目、模型、算法、结果还是检验？
3. 最值得保留的是内容还是结构？
4. 它更适合进论文还是进答辩？
5. 如果只能保留一句解释，这句话该怎么写？
