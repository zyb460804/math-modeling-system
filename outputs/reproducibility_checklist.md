# outputs/reproducibility_checklist.md

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 用于把数学建模作品的“代码—数据—参数—图表—论文结果”串成可复现清单，避免提交前出现“论文有结果、代码却跑不出来”或“能跑代码、却对不上正文”的断层。

---

## 一、总原则

1. 可复现不是“我本机跑过一次”，而是别人按说明也能得到同方向结论。
2. 复现链必须至少贯通五层：
   - 输入数据
   - 预处理
   - 主模型/求解
   - 图表与表格
   - 论文中的关键结果
3. 如果当前材料不完整，要明确写“待补数据 / 待补参数 / 待补脚本”，不能假装可复现。
4. 数模比赛里，允许数值因随机种子或浮点误差略有波动，但核心结论、排序、趋势和方案优先级应保持一致。

---

## 二、复现清单字段模板

以后整理复现包时，尽量统一列出：
- **目标模块**
- **输入文件**
- **输出文件**
- **核心参数**
- **运行命令/运行方式**
- **前置依赖**
- **预期结果**
- **与论文对应位置**
- **当前状态（可直接复现 / 需补充 / 需人工调整）**
- **最易出错点**

---

## 三、复现范围先判定

### 1. 最低可复现标准
至少应能复现：
- 1 个主结果表
- 1 组核心图
- 1 段关键模型结果
- 1 组检验或稳健性分析

### 2. 稳妥可提交标准
最好能复现：
- 预处理结果
- 主模型输出
- 检验输出
- 图表输出
- 摘要和结论中提到的关键数值

### 3. 冲高分标准
进一步做到：
- 不同脚本职责清晰
- 运行顺序一眼可懂
- 随机结果可控
- 中间结果可落盘保存
- 关键参数有说明表

---

## 四、数据与文件检查清单

### 1. 数据文件
- [ ] 原始数据文件是否齐全
- [ ] 文件名是否稳定，不依赖“最终版2”“最新修改”之类命名
- [ ] 缺失值、异常值处理是否在脚本里体现
- [ ] 若数据不能公开，是否提供字段说明或样例结构

### 2. 代码文件
- [ ] 是否区分预处理、主求解、画图、检验脚本
- [ ] 是否存在只在本机能跑的硬编码路径
- [ ] 是否写清主入口文件
- [ ] 是否删除与当前结果无关的废代码

### 3. 输出文件
- [ ] 是否能生成论文中出现的核心表格或图片
- [ ] 输出文件名是否能对应正文中的图表编号
- [ ] 是否保留关键中间结果，方便追溯

---

## 五、运行顺序检查清单

最稳妥的顺序通常是：
1. 数据读取
2. 数据预处理
3. 特征/指标构造
4. 主模型求解
5. 检验或稳健性分析
6. 画图与表格导出
7. 人工核对与论文一致性检查

### 必查项
- [ ] 是否存在明确的运行顺序说明
- [ ] 是否说明哪些脚本必须先跑
- [ ] 是否说明哪些文件由上一步自动生成
- [ ] 是否说明哪些步骤需要人工填入参数或路径

### 常见风险
- 直接先跑画图脚本，结果依赖文件却没生成
- 检验脚本和主模型脚本使用了不同版本的数据
- 论文中的最终图来自手工修改，但代码里没有对应步骤

---

## 六、参数与随机性检查清单

### 参数必查项
- [ ] 主参数是否集中写明
- [ ] 参数是否与论文中的设定一致
- [ ] 是否说明参数来源（题意 / 文献 / 调参 / 经验）
- [ ] 是否区分固定参数与待调参数

### 随机性必查项
- [ ] 是否设置随机种子
- [ ] 是否说明多次运行还是单次运行
- [ ] 如果结果有波动，是否说明允许波动范围
- [ ] 若使用智能优化 / 深度学习，是否保存最佳结果与平均表现

### 常见风险
- 论文写的参数和代码里实际参数不一致
- 一次偶然最优结果被当成稳定结论
- 调参结果没有记录，后续无法回到同一结论

---

## 七、图表与正文对齐清单

### 必查项
- [ ] 每张核心图是否能说清由哪个脚本生成
- [ ] 每个关键表是否能追溯到哪个结果文件
- [ ] 图表标题、坐标轴、对象名称是否和正文一致
- [ ] 摘要里的关键数值能否在代码输出中找到
- [ ] 结论中的排序、方案或趋势能否被结果文件支撑

### 常见风险
- 图画出来了，但和正文术语不一致
- 论文改过结果后，图表没有同步更新
- 图表来自 Excel 手工整理，代码无法回溯
- 摘要中的数字和正文/代码输出对不上

### 快速改法
- 给每张核心图补“来源脚本 + 来源结果文件”标记
- 给每个关键表补“生成路径”
- 把摘要、结论里出现的关键数字单独列成核对表

---

## 八、按题型补的最低复现包

### 1. 评价题
至少补齐：
- 指标矩阵来源
- 标准化脚本
- 权重结果
- 排序结果
- 1 组权重扰动或排序一致性检验

### 2. 预测题
至少补齐：
- 训练/测试划分说明
- 预测脚本
- 误差指标输出
- 预测图生成脚本
- 残差或对照结果

### 3. 优化题
至少补齐：
- 变量定义说明
- 目标函数与约束实现
- 求解器调用脚本
- 最优方案输出
- 1 组情景分析或参数扰动结果

### 4. 机理 / 仿真题
至少补齐：
- 参数表
- 方程或机制实现脚本
- 数值求解脚本
- 演化图
- 参数敏感性分析

### 5. 链式建模题
至少补齐：
- 中间层输出文件
- 中间层到决策层的输入映射
- 最终方案输出
- 中间层检验
- 决策层检验

---

## 九、提交前 10 分钟快扫

- [ ] 代码路径没有写死到个人电脑目录
- [ ] 核心脚本都能说明输入输出
- [ ] 至少一张核心图能从脚本直接生成
- [ ] 至少一个核心结果表能从脚本直接导出
- [ ] 摘要里的关键数字能对上结果文件
- [ ] 结论中的建议能对上模型输出
- [ ] 随机模型设置了种子或说明了波动处理
- [ ] 论文、图表、代码对同一对象使用同一术语
- [ ] 待补项已明确标出，没有伪装成“已完成”
- [ ] 运行顺序能在 1 分钟内讲清

---

## 十、最常见复现断层

- 代码能跑，但跑不出论文里的图表
- 论文有关键数字，但代码输出里找不到来源
- 预处理和主模型使用了不同版本的数据
- 图表是手工改的，无法追溯
- 参数是临时调出来的，没有记录
- 组合模型只写了主流程，没有保存中间层结果
- 深度学习或智能优化只保留最好一次，没有平均表现或稳定性说明

---

## 十一、最稳妥的交付说明模板

### 1. 代码包说明模板
- `01_preprocess.*`：读取原始数据并完成清洗/标准化，输出建模输入文件。
- `02_model.*`：执行主模型求解，输出核心结果。
- `03_validation.*`：完成误差分析、稳健性分析或情景分析。
- `04_plot.*`：根据结果文件生成论文图表。

### 2. 运行顺序模板
> 先运行预处理脚本生成标准输入，再运行主模型脚本得到核心结果，随后运行检验脚本确认稳定性，最后运行画图脚本生成论文所需图表。

### 3. 待补项模板
> 当前仍需补齐【缺失数据 / 参数来源 / 图表脚本 / 检验脚本】。在这些内容补齐前，本项目属于“部分可复现”，不能写成“完全可复现”。
