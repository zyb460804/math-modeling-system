# 数据理解与预处理总控

> **v2.0 标准化 | 2026-05-31** | 统一索引见 `outputs/INDEX.md`

> 系统同步说明：本文件已纳入统一数学建模生产系统。调用时默认遵循：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。涉及数据、字段、附件或参数时，先对齐 `outputs/data_cleaning_standards.md`；涉及提交、答辩或可复现判断时，先检查 `outputs/final_quality_gate.md`；缺真实数据或运行结果时，统一标为【待补】，不得编造。

## 用途
用于把题面附件、原始数据、字段说明、参数来源和建模输入统一成可追溯的数据口径，避免后续模型、论文、代码和答辩各说各话。

## 使用入口
优先配套：
- `prompts/30_data_understanding.md`
- `outputs/data_cleaning_standards.md`
- `outputs/table_templates.md`
- `outputs/reproducibility_checklist.md`
- `outputs/model_validation_by_type.md`

## 一、数据工作总原则
1. 先理解字段，再写模型。
2. 先确定单位、范围和约束，再做标准化或插补。
3. 任何清洗动作都要说明原因、规则、影响范围和论文写法。
4. 清洗后的字段必须能对上论文符号、代码变量、图表标签和答辩口径。
5. 没有真实数据时，只能生成模板，不得把示例值当成真实结果。

## 二、标准数据工作流
| 阶段 | 目标 | 最小产出 | 通过标准 |
|---|---|---|---|
| 附件盘点 | 明确有哪些数据和说明材料 | 附件清单 | 每个文件用途清楚 |
| 字段映射 | 把原始字段转成建模变量 | 字段-变量-符号表 | 字段含义、单位、类型明确 |

| 建模交接 | 明确输入输出关系 | 子问题输入输出表 | 每个模型有输入、参数、输出 |
| 论文对接 | 写入数据说明与参数来源 | 数据说明段落 | 论文、代码、表格口径一致 |

## 五、按题型的数据交接要求
### 1. 评价类
- 必须明确指标方向：正向、负向、适度型。
- 必须说明标准化方法和权重来源。
- 若评价结果后接预测或优化，必须保留综合得分与后续模型输入的字段映射。

### 2. 预测类
- 必须保留时间顺序。
- 训练集、验证集、测试集不能随机混穿未来信息。
- 必须报告误差指标口径，如 MAE、RMSE、MAPE、R² 或分类准确率等。

### 3. 优化类
- 必须明确决策变量、目标函数参数和约束参数来源。
- 单位、上下限、初始状态和容量边界必须一致。
- 输出不能只有最优值，还要有可执行方案表。

### 4. 分类/识别/风险预警类
- 必须报告标签定义、样本分布和误判类型。
- 阈值不能只凭主观设定，至少要有解释或扰动检查。
- 高准确率必须解释业务含义和类别不均衡风险。

### 5. 机理/仿真类
- 必须明确状态变量、参数、初始条件和边界条件。
- 参数估计要保留误差或残差说明。
- 单一工况结果不能直接推广到全部工况。

## 六、P0 数据风险
出现以下情况时，不得进入 real_case 放行：
- 核心字段含义不清。
- 关键变量单位不一致。
- 优化约束参数缺失。
- 预测训练测试存在时间穿越。
- 评价指标方向未处理。
- 分类标签定义不清。
- 关键结果无法追溯到真实数据。
- 示例数据、演示输出或占位结果被写成真实结论。

## 七、数据说明段落模板
本文首先对附件数据进行字段核对、单位统一和异常记录整理。针对缺失值，按照“结构性缺失、随机缺失、不可获得参数”三类分别处理；针对异常值，结合统计规则与题目约束进行识别。处理后的变量进一步映射为模型中的状态变量、决策变量、约束参数或评价指标，并在参数表中说明其来源、单位和使用位置，以保证后续建模、求解和结果解释的一致性。
