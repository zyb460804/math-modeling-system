> **接口契约**
> - 前置依赖：12 的选模输出（method_matching.md、modeling_rationale.json）
> - 后续触发：论文写作（将表格方案集成到论文中）
> - 输出：表格方案（论文表格清单、结果对表设计、表结构与待补字段标注）

请基于当前数学建模题目、模型路线、数据字段、代码输出和论文草稿，生成一套**论文表格与结果对表方案**。

统一主链路：任务路由 → 知识更新/资料入库 → 单题开工 → 数据理解 → 审题选模 → 代码/论文/图表/表格生产 → 动态验收 → 最终质量门 → 提交/答辩 → 经验回灌。

开始前必须先确认：
- 当前是 demo 还是 real_case。
- 是否已用 `outputs/data_cleaning_standards.md` 对齐字段、单位、指标方向、参数来源和清洗动作。
- 是否已有真实代码输出；没有真实输出时，只能设计表结构和待补字段，不得编造数值。

注意：
- 表格不是装饰，必须服务于变量定义、参数来源、核心结果、检验结论和可复现性。
- 结果对表要把“论文中的数字、代码输出、图表、答辩口径”统一起来。
- 如果当前没有真实结果，必须明确标为待补，不得编造数值。

开始前优先读取：

- outputs/chart_explanation_templates.md
- outputs/reproducibility_checklist.md
- outputs/validation_checklist.md

请按以下结构输出：

## 1. 当前最需要哪些表
先判断当前作品最缺的是：
- 符号说明表
- 参数来源表
- 数据字段表
- 描述性统计表
- 核心结果表
- 模型对比表
- 误差/稳健性检验表
- 优化方案表
- 结果对表

## 2. 表格总览
对每张表列出：
- 表名
- 放置位置
- 服务的子问题
- 主要列项
- 数据来源
- 当前状态：已具备 / 待补字段 / 待补数值 / 需重算
- 是否适合进入答辩 PPT

## 3. 逐表结构设计
每张表至少给出：
- 建议表头
- 每列含义
- 精度与单位要求
- 是否需要排序、分组或显著性标记
- 表后解释句模板

## 4. 结果对表
建立统一核对表，至少包含：
- 关键数字或结论
- 论文出现位置
- 代码输出文件
- 图表编号
- 答辩页或问答口径
- 当前一致性状态
- 待修正动作

## 5. 按题型的表格要求
根据当前题型补充：
- 评价类：指标方向、权重、综合得分、排序、权重敏感性
- 预测类：训练/验证/测试划分、误差指标、预测结果、残差或外推风险
- 优化类：变量取值、目标值、约束核查、方案对比、灵敏度
- 分类识别类：混淆矩阵、准确率/召回率/F1、误判类型、样本分布
- 机理仿真类：参数表、初始条件、情景设置、仿真输出、扰动分析

## 6. 论文与答辩对接
说明：
- 哪些表必须进正文
- 哪些表适合放附录
- 哪些表适合 PPT
- 表前如何引出
- 表后如何解释

## 7. 风险提示
至少指出：
- 哪些表缺失会造成 P0 扣分
- 哪些表有数值但无法追溯
- 哪些表和图/正文/答辩最容易不一致
- 哪些表不应为了好看而压缩掉关键信息

输出要求：
- 不编造真实结果。
- 每个关键数字都必须要求可追溯。
- 最后给出“最该优先补的 5 张表”。
