# 美赛 A-F 题型分题策略指南（MCM Decompose Strategy）

> **来源**：LLM-MM-Agent（NeurIPS 2025，usail-hkust/LLM-MM-Agent）的 `problem_decompse.py` 调度逻辑 + `prompt/decompose_prompt.json` 分题原则库 + `prompt/template.py` 中的 `DECOMPOSE_PRINCIPLE_PROMPT` / `TASK_DECOMPOSE_PROMPT` / `TASK_DESCRIPTION_PROMPT`。
>
> **用途**：当赛题进入分题（sub-problem decomposition）阶段时，按题型 A-F 和子任务数 3/4/5 选取对应的分题原则，指导如何把一道大题拆成 N 个聚焦、互不冗余的子任务。
>
> **配套文件**：`mcm-decompose-strategy.json`（同目录，原样复制的分题原则库，键 = 题型 A-F × 子任务数 3/4/5）。

---

## 一、decompose → refine 两步流程

MM-Agent 把分题拆成两步，对应 `template.py` 的两个 Prompt：

### 第 1 步：Decompose（粗拆，`TASK_DECOMPOSE_PROMPT`）

```
输入 = decompose_principle（本策略 json 按题型+任务数取出）
      + modeling_problem（题面）
      + problem_analysis（问题分析）
      + modeling_solution（建模方案）
      + tasknum（子任务数 N）
```

该步骤把整体方案拆成 **N 个子任务**，每个子任务用一段文字描述，子任务之间用 `---` 分隔。核心要求：
- 每个子任务聚焦一个明确侧面，**互不冗余**。
- 覆盖原方案的全部内容，**无遗漏**。
- 逻辑上构成从基础建模 → 增强/约束 → 验证/推广的递进路径。

### 第 2 步：Refine（细化，`TASK_DESCRIPTION_PROMPT`）

```
输入 = modeling_problem + problem_analysis + modeling_solution
      + decomposed_subtasks（第 1 步产出的 N 个子任务全文）
      + task_i（当前要细化的子任务序号 i）
```

该步骤对**每个子任务 i 逐个细化**：补全 scope、goals、methodology，明确数据输入、算法/模型选择，**不串入其他子任务的内容**。最终每个子任务拥有一段自洽、可独立交给下游（分析/建模/编码）执行的描述。

> **原则产出链路**：`DECOMPOSE_PRINCIPLE_PROMPT` 用历史赛题示例归纳出"每个子任务一般做什么"（即 json 内容）→ 存入 `decompose_prompt.json` → 运行时按题型+任务数取出注入 `TASK_DECOMPOSE_PROMPT`。本文件即这条链路的最终知识产物。

## 二、美赛 A-F 六题型分题策略摘要

> 以下从 json 原文提炼，不臆造。每题型的策略按子任务数 3/4/5 的共性主线来描述。

### A — 连续型（Continuous）

主线：**建机理模型 → 加约束/算极限 → 系统级交互/多主体 → 灵敏度与验证**。

- **子任务 1（建基）**：识别关键变量、建立支配方程（微分/概率/优化），用历史或经验数据标定，给出系统行为的初步仿真。强调在简化假设下抓住核心动力学。
- **子任务 2（约束/极限）**：给系统加物理/经济/物流约束，建成本函数或资源消耗模型，找出可行边界与临界点。
- **子任务 3（优化/评估）**：在约束下做优化或策略比选，量化多目标 trade-off，引入外部影响或长期趋势评估稳健性。
- **子任务 4（系统级交互）**（4/5 子任务时）：扩展到多主体、反馈、竞争、级联效应，可能引入博弈论/随机过程。
- **末子任务（灵敏度/验证）**：系统变参 → 影响传播 → 关键驱动因子 → 误差分析 → 模型适用性定论。

### B — 离散型（Discrete）

主线：**建离散模型 → 评估场景/trade-off → 多目标/资源约束 → 鲁棒性**。

- **子任务 1（建基）**：用优化/概率/仿真建模离散系统，归一化、加权度量，定义问题结构与变量关系。
- **子任务 2（场景评估）**：跑仿真/数值实验，评估不同输入或策略的影响，识别最优解或 trade-off，初步敏感性。
- **子任务 3（竞争/冲突）**（4/5 子任务时）：多目标优化、博弈论（Pareto/Nash）、冲突利益平衡。
- **子任务 4（资源约束）**（4/5 子任务时）：资源稀缺下的优先级与公平分配（动态规划、指标排序）。
- **末子任务（鲁棒性/验证）**：灵敏度、蒙特卡洛、扰动分析，检验模型在不确定与外部变化下的稳定性与泛化。

### C — 数据型（Data Insight）

主线：**数据预处理 → 评分/分类框架 → 预测建模 → 灵敏度/迭代**。

- **子任务 1（数据预处理）**：清洗、插补缺失、归一化/标准化，把原始数据变成结构化可用形态，降低噪声与偏差。
- **子任务 2（评分/分类体系）**：基于研究目标建指标/指数体系，量化关键属性关系，引入 ML/数据挖掘增强精度，产出可决策的排序或评分。
- **子任务 3（预测建模）**：时序/回归/ML 预测未来趋势，回测验证可靠性。
- **子任务 4（灵敏度/探索）**（4/5 子任务时）：系统变参量化影响，识别关键驱动因子与模型局限。
- **末子任务（迭代精化/评价）**（5 子任务时）：引入新数据校准、伪标签/数值导数、更新频率设计，最终用统计推断/回归/概率框架产出可解释结论。

### D — 运筹型（Operations Research / Network）

主线：**建网络/图模型 → 排序/优化 → 场景仿真 → 鲁棒性/推广**。

- **子任务 1（建基）**：用图/网络/统计模型量化系统关系，定义 KPI/指标，选合适算法刻画结构。
- **子任务 2（排序/优先级）**：多准则决策、网络分析、优化算法建立层次与相对重要性，识别关键干预点。
- **子任务 3（场景/动态）**：仿真/预测探索系统在时间、资源、效率约束下的演化，定位瓶颈与未来走向。
- **子任务 4（外部扰动/推广）**（4/5 子任务时）：引入外部冲击（环境/技术/政策），评估鲁棒性与适应性。
- **末子任务（泛化/推广）**（5 子任务时）：把方法迁移到新场景/领域，保留分析严谨性，体现可扩展性与通用性。

### E — 环境/政策型（Environment & Policy）

主线：**数据采集 → 模型构建（指标体系）→ 参数标定 → 模型分析 → 实证应用**。

- **子任务 1（基线模型）**：用回归/线性规划等建立简化基线，聚焦少数变量解释核心动态，设可检验假设。
- **子任务 2（精细化）**：加多变量/PCA/时序/优化，纳入反馈与相互依赖，用经验数据标定验证。
- **子任务 3（应用/策略）**：把模型用于具体场景，做情景规划/干预政策评估/优化，产出面向利益相关方的建议。
- **子任务 4（灵敏度/可靠性）**（4/5 子任务时）：系统变参、不确定性量化、稳定性分析，确保结论不过度依赖特定输入。
- **末子任务（实证推广）**（5 子任务时）：案例研究、假设情景模拟、跨情境泛化，提炼可行动洞察。

### F — 综合型（Comprehensive / Multi-faceted）

主线：**建量化框架 → 扩展定性维度 → 评估变化影响 → 推导策略建议**。

- **子任务 1（指标/框架）**：定义量化指标/准则/指数，确立变量关系，建可计算的基线框架。
- **子任务 2（多维度扩展）**：加社会文化/经济/环境影响，用多准则决策/层次/熵权法量化各因素相对重要性，呈现 trade-off。
- **子任务 3（变化影响评估）**：调参/仿真/情景分析，评估政策或外部变化对系统的级联影响，识别涌现行为。
- **子任务 4（策略/建议）**（4/5 子任务时）：综合各步产出，用统计推断/比较分析/优化模型导出平衡多目标的可实施策略。
- **末子任务（综合/沟通）**（5 子任务时）：把结果转译为政策/干预/指南，评估 trade-off、排序优先级，用清晰可执行的语言交付。

## 三、子任务数选择建议（3 / 4 / 5）

| 子任务数 | 适用情境 | 选取依据 |
|---------|---------|---------|
| **3** | 题目结构清晰、三问以内、侧重"建模→求解→验证"线性流程 | 国赛多数大题、美赛结构简单的题；每子任务粒度大、覆盖广 |
| **4** | 有独立的数据预处理/约束分析/多场景评估等额外侧面 | 美赛 A/B/C 常见四问；需单独拆出灵敏度或系统级交互 |
| **5** | 多子问题赛题、含数据采集+标定+迭代+推广全链路 | 美赛 C/E/F 数据驱动或政策导向题；需体现完整工程闭环 |

> **经验**：子任务数应与题面"问题 1/2/3…"的自然问数对齐；若题目只给大方向不给分问，按题型复杂度从 json 选 3 或 4；若需要展示数据采集→建模→标定→验证→推广全链路，选 5。宁少勿多——拆得太细会让每个子任务过浅。

## 四、与我们 system 的衔接

本策略服务于 `problem-doc-model-selector` skill 的 `analyze` 入口：

1. **触发时机**：analyze 完成题型判断后，若题目是多子问题赛题，按题型（A-F）从 `mcm-decompose-strategy.json` 取出对应子任务数的分题原则。
2. **产出衔接**：analyze 的机器可读契约 `paper_output/step1/problem_analysis.json` 中的 `sub_problems`（或 `questions`）字段，参考本策略的子任务定义来组织——每个子问题应包含 scope / goals / methodology，与 MM-Agent 的 decompose→refine 产物结构对齐。
3. **下游消费**：`modeling-paper-rubric-and-model-selector` 读取 `problem_analysis.json` 生成模型路线时，每个子问题可独立选模、独立验证；`model-code-and-result-generator` 可按子任务并行执行（对应 MM-Agent 的多 Agent 分发）。
4. **与国赛差异**：国赛（CUMCM）通常明确分问（问题一/二/三），直接按问拆即可，本策略作为"问内再拆"的参考；美赛（MCM/ICM）常给大方向不分问，本策略是分题的主依据。
